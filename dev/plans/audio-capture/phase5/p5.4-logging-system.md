# Deliverable 5.4: Logging System

## Phase

[Phase 5: Metadata, Logging & Recovery](../phase5-metadata-recovery.md)

## Prerequisites

- No code dependencies (build first in Phase 5)
- Python `logging` module or equivalent available

## Description

Implement a structured logging system that covers all pipeline events. Logs are the primary debugging and monitoring interface for the pipeline. All log entries should be structured (JSON format) to enable machine parsing.

### Log Categories

| Category      | Description                                    | Examples                                    |
|---------------|------------------------------------------------|---------------------------------------------|
| `capture`     | Capture process lifecycle events               | Start, stop, restart, EOF                   |
| `encoder`     | Encoder process lifecycle events               | Start, write, close, exit, failure          |
| `split`       | Segment transition events                      | Boundary reached, segment started/completed |
| `boundary`    | Boundary queue mutations                       | Add, update, remove, lock, replace          |
| `timing`      | External timing data events                    | Refresh, track change, drift measurement    |
| `recovery`    | Failure and recovery events                    | Crash detected, restart, fallback, skip     |
| `pipeline`    | Top-level pipeline lifecycle                   | Pipeline start, stop, configuration         |

### Log Entry Format

```json
{
    "timestamp": "2026-03-04T14:30:15.123Z",
    "level": "INFO",
    "category": "split",
    "event": "segment_completed",
    "data": {
        "segment_index": 3,
        "start_frame": 10800000,
        "end_frame": 19440000,
        "duration_frames": 8640000,
        "output_file": "segment_000003.mp3"
    },
    "frame_position": 19440000
}
```

### Log Levels

| Level   | Usage                                                  |
|---------|--------------------------------------------------------|
| DEBUG   | Frame-level details, chunk processing, minor drift     |
| INFO    | Segment transitions, process lifecycle, timing refresh |
| WARNING | Moderate drift, retry attempts, non-critical issues    |
| ERROR   | Process crashes, encoder failures, critical drift      |

### Implementation Details

1. Use Python's `logging` module with a custom JSON formatter
2. Support multiple outputs: console (human-readable) + file (JSON)
3. Include `frame_position` in every log entry for timeline correlation
4. Log file rotation: daily or by size (e.g., 10MB max)

### Interface

```python
class PipelineLogger:
    def __init__(self, log_dir: str = "./logs", console_level: str = "INFO",
                 file_level: str = "DEBUG")

    def log(self, level: str, category: str, event: str,
            data: dict | None = None, frame_position: int = 0) -> None

    # Convenience methods
    def capture_event(self, event: str, **data) -> None
    def encoder_event(self, event: str, **data) -> None
    def split_event(self, event: str, **data) -> None
    def boundary_event(self, event: str, **data) -> None
    def timing_event(self, event: str, **data) -> None
    def recovery_event(self, event: str, **data) -> None
```

## Completion Criteria

1. All pipeline events produce structured JSON log entries
2. Every log entry includes `timestamp`, `level`, `category`, `event`, and `frame_position`
3. Console output is human-readable; file output is JSON (one entry per line)
4. Log levels are used appropriately per the level table
5. Log files are created in a configurable directory
6. Logging does not block or slow the main pipeline loop
