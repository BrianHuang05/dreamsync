# Deliverable 5.3: Failure Handling & Recovery

## Phase

[Phase 5: Metadata, Logging & Recovery](../phase5-metadata-recovery.md)

## Prerequisites

- Phase 3 complete (encoder and capture process managers)
- Deliverable 5.4 complete (logging system available)

## Description

Implement recovery strategies for the two main failure modes in the pipeline: capture FFmpeg process crashes and encoder FFmpeg process failures. The pipeline should be resilient and continue operating through transient failures.

### Failure Mode 1: Capture FFmpeg Crash

The capture process may exit unexpectedly due to device disconnection, driver issues, or resource exhaustion.

**Detection:**
- EOF on stdout pipe
- Process exit with non-zero code
- `is_alive()` returns False unexpectedly

**Recovery procedure:**

```
1. Detect EOF or process exit
2. Log event with timestamp and exit code
3. Record gap: note the frame position where capture was lost
4. Wait briefly (100-500ms) for device stabilization
5. Restart capture process
6. Resume frame counter from where it stopped
7. Log gap duration and frame count
```

**Gap handling:**
- The gap (period of no audio) should be recorded in the current segment's sidecar metadata
- Option A: Pad the gap with silence (write zero bytes to encoder)
- Option B: Leave the gap (segment will be shorter than planned)
- Default: Option B (leave gap, document in sidecar)

### Failure Mode 2: Encoder Process Failure

An encoder may fail due to disk space, FFmpeg error, or corrupted pipe.

**Detection:**
- Write to stdin raises `BrokenPipeError`
- Process exits before stdin is closed
- Non-zero exit code after `wait()`

**Recovery cascade:**

```
1. Detect encoder failure
2. Log error with segment details
3. Attempt retry:
   a. Start new encoder for same segment
   b. If buffer has the data, replay it
   c. If no buffer: proceed to fallback
4. Fallback: write raw PCM to disk
   a. Save as .raw file with same naming scheme
   b. Record format details in sidecar for later conversion
5. Last resort: skip segment
   a. Log skipped segment
   b. Start next encoder and continue
```

### Interface

```python
class RecoveryManager:
    def __init__(self, capture_manager, encoder_manager, logger)

    def handle_capture_failure(self, frame_position: int) -> None:
        """Detect and recover from capture process failure."""

    def handle_encoder_failure(self, segment_info: dict) -> str:
        """Handle encoder failure. Returns: 'retried', 'fallback', or 'skipped'."""
```

### Configuration

| Parameter             | Default | Description                        |
|-----------------------|---------|------------------------------------|
| `capture_restart_delay`| 0.2s   | Delay before capture restart       |
| `max_capture_retries` | 5       | Max consecutive capture restarts   |
| `encoder_retry_count` | 1       | Encoder retry attempts before fallback |
| `gap_strategy`        | "leave" | "leave" or "pad_silence"           |

## Completion Criteria

1. Capture FFmpeg crash is detected within 1 second
2. Capture automatically restarts and resumes frame counting
3. Gap duration is logged and recorded in segment sidecar
4. Encoder failure triggers retry, then fallback to raw PCM, then skip
5. Pipeline continues operating after any single failure
6. No more than `max_capture_retries` consecutive restarts (prevents infinite loop)
7. All failures are logged with timestamps and context
