# Deliverable 2.3: PCM Stream Reader

## Phase

[Phase 2: PCM Capture Engine](../phase2-pcm-capture.md)

## Prerequisites

- Deliverable 2.2 complete (capture process manager functional)

## Description

Implement a reader that consumes raw PCM bytes from the capture process stdout in fixed-size chunks aligned to frame boundaries. The reader is the first stage of the processing pipeline and must guarantee that every chunk contains a whole number of frames.

### Key Constants

| Constant          | Value   | Derivation                    |
|-------------------|---------|-------------------------------|
| `SAMPLE_RATE`     | 48000   | Configured in capture         |
| `CHANNELS`        | 2       | Stereo                        |
| `BYTES_PER_SAMPLE`| 2       | 16-bit (s16le)                |
| `BYTES_PER_FRAME` | 4       | `CHANNELS * BYTES_PER_SAMPLE` |
| `BYTES_PER_SECOND`| 192000  | `SAMPLE_RATE * BYTES_PER_FRAME`|

### Chunk Size Calculation

For a configurable chunk duration (default 100ms):

```
chunk_bytes = int(chunk_duration_seconds * BYTES_PER_SECOND)
chunk_bytes = chunk_bytes - (chunk_bytes % BYTES_PER_FRAME)  # align to frame boundary
```

100ms example: `19200 bytes` (4800 frames)

### Implementation Details

1. Read exactly `chunk_bytes` from the capture stdout pipe per iteration
2. Handle partial reads: accumulate until a full chunk is available
3. On EOF (capture process exited): signal end-of-stream to downstream
4. Yield chunks as `bytes` objects to the split logic consumer

### Interface

```
read_chunks(stream, chunk_ms: int = 100) -> Iterator[bytes]
```

Yields frame-aligned PCM byte chunks until EOF.

## Completion Criteria

1. Reader yields chunks of exactly `chunk_bytes` bytes
2. Every chunk contains a whole number of frames (chunk size divisible by 4)
3. Partial reads at stream boundaries are accumulated correctly (no short chunks except final)
4. EOF from capture process cleanly terminates the iterator
5. Chunk duration is configurable (20ms to 100ms tested)
