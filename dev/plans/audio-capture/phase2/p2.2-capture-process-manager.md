# Deliverable 2.2: Capture Process Manager

## Phase

[Phase 2: PCM Capture Engine](../phase2-pcm-capture.md)

## Prerequisites

- Deliverable 2.1 complete (device discovery functional)

## Description

Implement a manager that spawns and controls the FFmpeg capture process. The capture process reads from the CABLE Output device via DirectShow and writes raw PCM (s16le, stereo, 48kHz) to its stdout pipe.

### FFmpeg Capture Command

```
ffmpeg -hide_banner -loglevel warning
  -thread_queue_size 1024
  -f dshow -i audio="CABLE Output (VB-Audio Virtual Cable)"
  -ac 2 -ar 48000
  -f s16le -acodec pcm_s16le
  pipe:1
```

### Implementation Details

1. **Spawn:** Start FFmpeg as a subprocess with `stdout=PIPE` and `stderr=PIPE`
2. **Device name:** Use device name from Deliverable 2.1 discovery function
3. **Lifecycle management:**
   - `start()` - spawn the capture process
   - `stop()` - send terminate signal, wait for exit
   - `is_alive()` - check if process is still running
   - `restart()` - stop then start
4. **Error handling:** Monitor stderr for FFmpeg errors; detect unexpected exit
5. **stdout access:** Expose the stdout pipe for the PCM Stream Reader (2.3) to consume

### Configuration

| Parameter          | Default | Description                    |
|--------------------|---------|--------------------------------|
| `sample_rate`      | 48000   | Capture sample rate in Hz      |
| `channels`         | 2       | Number of audio channels       |
| `thread_queue_size`| 1024    | FFmpeg input thread queue size  |

## Completion Criteria

1. FFmpeg capture process spawns successfully targeting the discovered device
2. Process stdout produces continuous raw PCM data
3. `stop()` terminates the process cleanly (no zombie processes)
4. `is_alive()` correctly reports process state
5. Unexpected process exit is detected within 1 second
