# Deliverable 4.1: Boundary Queue Manager

## Phase

[Phase 4: Dynamic Rolling Window](../phase4-dynamic-updates.md)

## Prerequisites

- Deliverable 3.1 complete (segment boundary computation)
- Deliverable 3.3 complete (split logic algorithm)

## Description

Replace the static boundary list from Phase 3 with a mutable, sorted queue of upcoming segment boundaries. The queue supports insertion, update, and removal of future boundaries while the pipeline is actively processing audio.

### Data Structure

A sorted list (or priority queue) of boundary entries:

```python
@dataclass
class BoundaryEntry:
    frame_position: int      # cumulative frame count where split occurs
    segment_index: int       # sequential segment number
    metadata: dict | None    # optional song metadata for file naming
    locked: bool = False     # True if within safety margin (immutable)
```

### Operations

| Operation   | Description                                                  |
|-------------|--------------------------------------------------------------|
| `add(entry)`    | Insert a new boundary, maintaining sorted order          |
| `update(index, new_frame_position)` | Move a future boundary to a new position |
| `remove(index)` | Remove a future boundary                                |
| `peek_next()`   | Return the next upcoming boundary without removing it    |
| `pop_next()`    | Return and remove the next boundary (when split occurs)  |
| `replace_future(new_boundaries)` | Replace all unlocked boundaries with new list |
| `lock(index)`   | Mark a boundary as immutable (within safety margin)      |

### Thread Safety

If capture and plan refresh run on separate threads, all queue operations must be thread-safe. Use a `threading.Lock` to guard mutations.

### Integration with Split Logic

The split logic (3.3) currently reads from a static `boundaries[]` list. Replace this with calls to `peek_next()` and `pop_next()` on the boundary queue:

```python
# Before (static):
frames_remaining = boundaries[segment_index] - current_frame

# After (dynamic):
next_boundary = boundary_queue.peek_next()
frames_remaining = next_boundary.frame_position - current_frame
```

## Completion Criteria

1. Queue maintains boundaries in sorted order by `frame_position`
2. `add()`, `update()`, `remove()` correctly modify the queue
3. `peek_next()` returns the nearest upcoming boundary without mutation
4. `pop_next()` returns and removes the nearest boundary
5. `replace_future()` replaces all unlocked boundaries while preserving locked ones
6. Thread-safe under concurrent access (if applicable)
7. Split logic works identically with queue as it did with static list
