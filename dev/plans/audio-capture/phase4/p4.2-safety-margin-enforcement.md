# Deliverable 4.2: Safety Margin Enforcement

## Phase

[Phase 4: Dynamic Rolling Window](../phase4-dynamic-updates.md)

## Prerequisites

- Deliverable 4.1 complete (boundary queue manager)

## Description

Implement a safety margin that prevents modification of boundaries that are too close to the current frame position. This prevents race conditions where a boundary is moved or removed while the split logic is about to process it.

### Safety Margin

```
safety_margin_seconds = 0.5  # configurable, 0.5 to 1.0 seconds
safety_margin_frames = round(safety_margin_seconds * sample_rate)
# 0.5s -> 24,000 frames
# 1.0s -> 48,000 frames
```

### Rules

A boundary is **locked** (immutable) when:

```
boundary.frame_position - current_frame <= safety_margin_frames
```

**Locked boundaries cannot be:**
- Updated (moved to a different frame position)
- Removed from the queue

**Locked boundaries can be:**
- Read (peek/pop)
- Processed normally by the split logic

### Implementation

On every queue mutation attempt (`update()`, `remove()`, `replace_future()`):

1. Compute the lock threshold: `lock_threshold = current_frame + safety_margin_frames`
2. For any boundary with `frame_position <= lock_threshold`: reject the mutation
3. Return a status indicating whether the operation succeeded or was rejected

### Periodic Lock Sweep

Optionally, run a periodic sweep that marks boundaries as locked:

```python
def update_locks(self, current_frame: int) -> None:
    threshold = current_frame + self.safety_margin_frames
    for entry in self.queue:
        if entry.frame_position <= threshold:
            entry.locked = True
        else:
            break  # queue is sorted, no need to check further
```

This can be called before each plan refresh.

## Completion Criteria

1. Boundaries within safety margin frames of current position cannot be updated or removed
2. Boundaries beyond safety margin can be freely modified
3. `replace_future()` preserves all locked boundaries
4. Safety margin is configurable (tested with 0.5s and 1.0s)
5. Mutation attempts on locked boundaries return a clear rejection signal
6. Lock status updates correctly as `current_frame` advances
