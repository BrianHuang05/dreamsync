## Goal

Implement `cached_compile_show()` — a thin wrapper around `compile_show()` that checks the cache before compiling — and `path_based_track_id()` — a helper that generates filesystem-safe cache keys from mp3 file paths (for offline/non-Spotify usage).

## `cached_compile_show()` — Logic

```python
def cached_compile_show(structure, profile=None, *, cache, track_id, **compile_kwargs):
    track_id = _sanitize_track_id(track_id)

    # 1. Check cache
    timeline = cache.get(track_id, profile)
    if timeline is not None:
        logger.info("Cache HIT for track=%s profile_fp=%s",
                     track_id, profile_fingerprint(profile))
        return (timeline, True)

    # 2. Cache miss — compile
    logger.info("Cache MISS for track=%s profile_fp=%s — compiling",
                 track_id, profile_fingerprint(profile))
    from dreamsync.compiler.compile import compile_show
    timeline = compile_show(structure, profile, **compile_kwargs)

    # 3. Store in cache
    cache.put(track_id, timeline, profile)

    return (timeline, False)
```

**Import placement**: `compile_show` is imported inside the function body (lazy import) to avoid circular imports — `cache.py` is a utility module that shouldn't force-load the compiler on import.

**`compile_kwargs` passthrough**: All keyword arguments accepted by `compile_show()` are forwarded. This includes `seed`, `intro_intensity`, `outro_intensity`, `peak_boost`, `buildup_ramp`, `bridge_reduction`, `default_fade_beats`, `max_fade_beats`. The caller decides what to pass.

**Non-goal**: The `compile_kwargs` are NOT part of the cache key. If a user changes `intro_intensity` and recompiles the same song/profile, they'll get the old cached result. This is documented in the parent plan's Non-Goals section. Users must `cache-clear` to recompile with different tuning params.

## `path_based_track_id()` — Logic

```python
import re

def path_based_track_id(file_path: Path | str) -> str:
    path = Path(file_path).resolve()
    stem = re.sub(r"[^a-zA-Z0-9_-]", "_", path.stem)  # sanitize stem
    if not stem or stem == "_":
        stem = "unknown"
    path_hash = hashlib.sha256(str(path).encode("utf-8")).hexdigest()[:8]
    return f"{stem}_{path_hash}"
```

**Why include the stem?** Readability. Cache directories named `Bohemian_Rhapsody_a1b2c3d4` are easier to inspect than pure hashes.

**Why hash the full path?** Two files named `song.mp3` in different directories must get different cache keys. The hash of the absolute path disambiguates.

**Examples:**

| File Path | Track ID |
|-----------|----------|
| `/home/brian/music/Bohemian Rhapsody.mp3` | `Bohemian_Rhapsody_3f7a9c21` |
| `/home/brian/other/Bohemian Rhapsody.mp3` | `Bohemian_Rhapsody_8d4e1b05` |
| `/music/song.mp3` | `song_a2c4e6f8` |

## `_sanitize_track_id()` — Logic

```python
def _sanitize_track_id(track_id: str) -> str:
    sanitized = re.sub(r"[^a-zA-Z0-9_-]", "_", track_id)
    sanitized = sanitized[:128]
    if not sanitized or sanitized == "_" * len(sanitized):
        raise ValueError(f"Invalid track_id: {track_id!r} (empty after sanitization)")
    return sanitized
```

- Spotify track IDs (22 alphanumeric chars) pass through unchanged.
- Path-based IDs from `path_based_track_id()` are already safe (but the sanitizer is a defense-in-depth layer).
- Empty strings and strings that are all special characters raise `ValueError`.

class TestPathBasedTrackId:
    def test_determinism_and_different_paths(self):
        id1 = path_based_track_id("/music/song.mp3")
        id2 = path_based_track_id("/music/song.mp3")
        id3 = path_based_track_id("/other/song.mp3")

        assert id1 != id3                        # different paths → different IDs

class TestSanitizeTrackId:
