## Description

The `DriftDetector` monitors the relationship between the pipeline's audio frame counter (actual captured frames) and wall-clock time (expected frames based on elapsed seconds and sample rate). If the audio device captures faster or slower than the nominal sample rate, boundaries computed from timing data will gradually drift out of alignment with the actual audio content.

This sub-component wires the `DriftDetector` into `CaptureOrchestrator.__init__()`. The detector needs:

1. **`sample_rate`** — to convert between frames and seconds.
2. **`boundary_queue`** — the same shared `BoundaryQueue` so it can adjust future boundary positions when drift exceeds the correction threshold.
3. **Three threshold values** — to classify drift severity:
   - `warning_threshold` (default 0.1s / 4800 frames): Log a warning but take no action.
   - `correction_threshold` (default 0.5s / 24000 frames): Automatically shift all unlocked future boundaries to compensate.
   - `critical_threshold` (default 2.0s / 96000 frames): Log an error; correction is still applied but the drift magnitude suggests a systemic problem.

The `DriftDetector` must share the **same** `BoundaryQueue` instance as the `TimingIntegrator` and `DynamicSplitProcessor`. This is critical because when drift correction adjusts boundary positions, those adjusted positions must be visible to the split processor (which reads from the queue) and must respect the queue's safety-margin locking (which prevents modification of imminent boundaries).

### How Drift Correction Works (Reference)

When `DriftDetector.measure_and_correct()` detects drift exceeding the correction threshold:

1. It calls `self._queue.entries()` to snapshot all current boundaries.
2. For each unlocked entry, it subtracts `drift_frames` from `frame_position` (if the pipeline is running ahead) or adds it (if running behind).
3. It calls `self._queue.replace_future(adjusted_entries, current_frame)` to atomically replace unlocked boundaries with adjusted ones.
4. Locked boundaries (within `safety_margin_frames` of the current frame) are preserved unchanged by `replace_future()`.

## Implementation Details

### File
`src/dreamsync/capture/orchestrator.py`

### Import
```python
from dreamsync.capture.drift_detector import DriftDetector
```

### Wiring in `__init__()`

Add the following to `CaptureOrchestrator.__init__()`, after the `BoundaryQueue` has been created (D3.2):

```python
# --- Drift detection ---
self._drift = DriftDetector(
    sample_rate=config.sample_rate,
    boundary_queue=self._boundary_queue,
    warning_threshold=config.drift_warning_threshold,
    correction_threshold=config.drift_correction_threshold,
    critical_threshold=config.drift_critical_threshold,
)
```

### Parameter Mapping

| `OrchestratorConfig` field | `DriftDetector.__init__()` parameter | Default value |
|---------------------------|--------------------------------------|---------------|
| `sample_rate` | `sample_rate` | `48000` |
| `drift_warning_threshold` | `warning_threshold` | `0.1` |
| `drift_correction_threshold` | `correction_threshold` | `0.5` |
| `drift_critical_threshold` | `critical_threshold` | `2.0` |
| (shared object) `self._boundary_queue` | `boundary_queue` | N/A |

### Ordering Constraints

The `DriftDetector` must be created **after** the `BoundaryQueue` (D3.2) because it takes the queue as a constructor argument. The full `__init__()` ordering:

1. Store `config`
2. Create `PipelineLogger`
3. Create `AudioBuffer` (`self._buffer`)
4. Create `BoundaryQueue` (`self._boundary_queue`) — D3.2
5. Create `TimingIntegrator` (`self._timing`) — D3.2
6. **Create `DriftDetector` (`self._drift`)** — this sub-component
7. Create `DynamicSplitProcessor` (`self._split`) — D3.1

### Shared BoundaryQueue Diagram

```
                BoundaryQueue (single instance)
               /          |            \
              /            |             \
TimingIntegrator    DriftDetector    DynamicSplitProcessor
(writes via         (reads entries,   (reads via peek/pop,
 replace_future)     adjusts via       consumes boundaries
                     replace_future)    at split points)
```

All three components reference the same `BoundaryQueue` object. Thread safety is guaranteed by the queue's internal `threading.Lock`.

### No Cleanup Needed

Unlike the `TimingIntegrator` (which has a background timer that must be stopped), the `DriftDetector` is stateless between measurements and does not require explicit cleanup in `stop()`. It is called on-demand by the consumer loop (D3.5) and does not spawn threads.
