# D3.3 — External Timing API

## Deliverable
D3 — Boundary Control Path

## Prerequisites
- D3.2 — `TimingIntegrator` wired as `self._timing` in `CaptureOrchestrator`
- D3.2 — `BoundaryQueue` wired as `self._boundary_queue` in `CaptureOrchestrator`
- `TimingIntegrator.update(timing_data)` returns `int` (number of new boundaries)
- `TimingIntegrator.on_track_change(timing_data)` returns `int`
- `TimingIntegrator.start_periodic_refresh(fetch_fn)` starts a background timer
- `segment_boundary.compute_boundaries()` converts durations to frame positions

## Description

The `CaptureOrchestrator` needs a public API that the session layer (e.g., `LocalShowSession`, Spotify queue watcher) can call to push timing data into the pipeline. Rather than exposing the `TimingIntegrator` directly, the orchestrator provides three thin wrapper methods that delegate to the integrator while maintaining encapsulation.

These methods are the **only** way external code interacts with the boundary control path:

1. **`update_timing(timing_data)`** — One-shot push of timing data. Used when the session layer fetches updated queue information from Spotify. The integrator converts song durations into frame-level boundaries, computes absolute positions based on the current buffer frame count, and replaces future (unlocked) boundaries in the queue.

2. **`on_track_change(timing_data)`** — Convenience method for track-change events. Semantically identical to `update_timing()` but logs a track-change event for diagnostics. Called when the session layer detects that the currently playing song has changed.

3. **`start_periodic_timing(fetch_fn)`** — Starts a background timer that calls `fetch_fn()` every `timing_refresh_interval` seconds and feeds the result into `update()`. Used when the session layer has a polling-based timing source rather than event-driven updates.

### Timing Data Format

All three methods accept (or produce via `fetch_fn`) a timing data dictionary with this structure:

```python
{
    "song_durations": [180.0, 240.0, 195.0],
    "current_playback_time": 45.0,
    "current_song": {
        "song_title": "Song Name",
        "artist": "Artist Name",
        "album": "Album Name",
    }
}
```

**Field semantics:**

| Field | Type | Description |
|-------|------|-------------|
| `song_durations` | `list[float]` | Durations in seconds. Index 0 is the currently playing song; remaining entries are upcoming songs in queue order. |
| `current_playback_time` | `float` | Seconds elapsed into the currently playing song (index 0). Used to compute the remaining time until the first boundary. |
| `current_song` | `dict` | Metadata for the currently playing song. Stored in `BoundaryEntry.metadata` for filename generation and sidecar files. |

**How boundaries are computed from timing data:**

1. `remaining_time = song_durations[0] - current_playback_time` gives the time until the first split.
2. Each subsequent duration adds another boundary.
3. `segment_boundary.compute_boundaries()` converts these durations to cumulative frame positions relative to the current frame.
4. The `TimingIntegrator` adds `current_frame` to each relative position to get absolute frame positions.
5. These absolute positions are wrapped in `BoundaryEntry` objects and pushed to the queue via `replace_future()`.

## Implementation Details

### File
`src/dreamsync/capture/orchestrator.py`

### Method Signatures

```python
class CaptureOrchestrator:
    # ... (existing __init__ and lifecycle methods)

    def update_timing(self, timing_data: dict) -> int:
        """Push new timing data and refresh the boundary queue.

        Call this whenever updated song queue information is available
        (e.g., after polling the Spotify API).

        Parameters
        ----------
        timing_data:
            Dict with keys ``song_durations`` (list[float]),
            ``current_playback_time`` (float), and optionally
            ``current_song`` (dict with song metadata).

        Returns
        -------
        Number of new boundaries applied to the queue.
        """
        return self._timing.update(timing_data)

    def on_track_change(self, timing_data: dict) -> int:
        """Handle a track-change event with immediate boundary refresh.

        Semantically identical to :meth:`update_timing` but logs the
        event as a track change for diagnostics.

        Parameters
        ----------
        timing_data:
            Same format as :meth:`update_timing`.

        Returns
        -------
        Number of new boundaries applied to the queue.
        """
        return self._timing.on_track_change(timing_data)

    def start_periodic_timing(self, fetch_fn: Callable[[], dict | None]) -> None:
        """Start background periodic timing refresh.

        A background timer will call *fetch_fn* every
        ``config.timing_refresh_interval`` seconds.  If *fetch_fn*
        returns a dict, it is passed to :meth:`update_timing`.  If it
        returns ``None``, the refresh is skipped.

        Parameters
        ----------
        fetch_fn:
            Callable that returns timing data (same format as
            :meth:`update_timing`) or ``None`` if no data is available.
        """
        self._timing.start_periodic_refresh(fetch_fn)
```

### Delegation Chain

```
Session Layer (e.g., LocalShowSession)
    |
    +-- orchestrator.update_timing(timing_data)
    |       |
    |       +-- self._timing.update(timing_data)
    |               |
    |               +-- compute_boundaries(durations, playback_time, sample_rate)
    |               +-- self._queue.replace_future(entries, current_frame)
    |
    +-- orchestrator.on_track_change(timing_data)
    |       |
    |       +-- self._timing.on_track_change(timing_data)
    |               |
    |               +-- self._timing.update(timing_data)  (same path)
    |
    +-- orchestrator.start_periodic_timing(fetch_fn)
            |
            +-- self._timing.start_periodic_refresh(fetch_fn)
                    |
                    +-- Timer thread calls fetch_fn() -> timing.update(data)
```

### Usage Example (from session layer)

```python
# One-shot update after polling Spotify
timing = {
    "song_durations": [210.0, 195.0, 240.0],
    "current_playback_time": 30.0,
    "current_song": {"song_title": "Bohemian Rhapsody", "artist": "Queen"},
}
n = orchestrator.update_timing(timing)
# n == 3 (three boundaries: end of songs 1, 2, 3)

# Track change detected
new_timing = {
    "song_durations": [195.0, 240.0, 180.0],
    "current_playback_time": 0.0,
    "current_song": {"song_title": "Stairway to Heaven", "artist": "Led Zeppelin"},
}
n = orchestrator.on_track_change(new_timing)

# Or, start automatic polling
def fetch_spotify_queue() -> dict | None:
    # Poll Spotify API, return timing dict or None
    ...

orchestrator.start_periodic_timing(fetch_spotify_queue)
```

## Tests

Test file: `dev/tests/test_orchestrator.py`

- [ ] `test_timing_update_adds_boundaries` — Construct a `CaptureOrchestrator`. Call `update_timing()` with timing data containing `song_durations=[180.0, 240.0]` and `current_playback_time=0.0`. Assert: (a) the return value is `2` (two boundaries), (b) `len(orchestrator._boundary_queue) == 2`, (c) the boundary frame positions are correct: first boundary at `180.0 * 48000 = 8_640_000`, second at `(180.0 + 240.0) * 48000 = 20_160_000` (both relative to the current frame, which is 0 at startup).

- [ ] `test_track_change_immediate_refresh` — Construct a `CaptureOrchestrator`. Call `update_timing()` with initial timing data (3 songs). Then call `on_track_change()` with new timing data (2 songs). Assert: (a) the return value reflects the new boundary count, (b) the boundary queue now contains entries matching the new timing data (old unlocked boundaries were replaced), (c) boundary positions are recomputed from the new durations.

- [ ] `test_start_periodic_timing_delegates` — Construct a `CaptureOrchestrator`. Create a mock `fetch_fn` that returns a timing data dict. Call `start_periodic_timing(fetch_fn)`. Assert: (a) `orchestrator._timing._running` is `True`, (b) `orchestrator._timing._fetch_fn` is the mock function. Call `orchestrator._timing.stop()` to clean up.

- [ ] `test_update_timing_returns_count` — Construct a `CaptureOrchestrator`. Call `update_timing()` with 0 durations (empty list). Assert return value is `0`. Call `update_timing()` with 1 duration. Assert return value is `1`. Call `update_timing()` with 5 durations. Assert return value is `5`. This verifies the return value directly reflects how many boundaries were applied.
