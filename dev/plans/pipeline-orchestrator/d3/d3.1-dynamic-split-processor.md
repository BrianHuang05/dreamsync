## Description

The existing `SplitProcessor` in `split_logic.py` accepts a static `boundaries: list[int]` at construction time. This works for offline splitting but cannot handle the orchestrator's live pipeline where boundaries arrive dynamically from the `BoundaryQueue` as timing data flows in from the session layer (Spotify queue watcher).

`DynamicSplitProcessor` is an adapter that replaces the static boundary list with live reads from a `BoundaryQueue`. On each call to `process_chunk()`, it checks the queue for the next upcoming boundary and splits the PCM data at the exact frame position. When a boundary is reached, it rotates the encoder (closes the current segment's encoder and starts a new one via the `start_encoder` callback) and fires the `on_segment_complete` callback so the orchestrator can write metadata sidecars, log events, etc.

The class mirrors the public API of `SplitProcessor` (`start()`, `process_chunk()`, `finish()`) so the consumer loop can use either interchangeably, but it is a separate class because the internal splitting logic is fundamentally different: instead of indexing into a pre-computed list, it pulls boundaries from a thread-safe queue that may be updated concurrently by the `TimingIntegrator`.

### Class Definition

```python
class DynamicSplitProcessor:
    """SplitProcessor that reads boundaries from a BoundaryQueue.

    Instead of a static list of frame boundaries, this processor checks
    the BoundaryQueue on every chunk for the next split point.  Boundaries
    may be added, replaced, or adjusted by TimingIntegrator and
    DriftDetector while the processor is running.

    Parameters
    ----------
    boundary_queue:
        Thread-safe queue of upcoming segment boundaries.
    start_encoder:
        Callable that receives ``(segment_index,)`` and returns an object
        with ``write(bytes)`` and ``close()`` methods (typically an
        ``EncoderProcess`` that has already been started).
    on_segment_complete:
        Optional callback ``(segment_index, start_frame, end_frame)``
        invoked when a segment is finalized (encoder closed).
    """

    def __init__(
        self,
        boundary_queue: BoundaryQueue,
        start_encoder: Callable[[int], object],
        on_segment_complete: Callable[[int, int, int], None] | None = None,
    ) -> None:
        self._queue = boundary_queue
        self._start_encoder = start_encoder
        self._on_segment_complete = on_segment_complete
        self._current_frame: int = 0
        self._segment_index: int = 0
        self._segment_start_frame: int = 0
        self._encoder = None
        self._finished = False

    @property
    def current_frame(self) -> int:
        """Total audio frames processed so far."""
        return self._current_frame

    @property
    def segment_index(self) -> int:
        """Index of the currently active segment (0-based)."""
        return self._segment_index
```

### `start()` Method

```python
    def start(self) -> None:
        """Initialize the first encoder (segment 0)."""
        self._encoder = self._start_encoder(self._segment_index)
```

Called once before the first `process_chunk()`. Creates the encoder for segment 0. The `start_encoder` callback is responsible for constructing and starting an `EncoderProcess` (or mock) and returning it.

### `process_chunk(chunk)` Method

This is the core splitting logic. It processes a single PCM chunk (typically 100 ms / 19200 bytes), consulting the `BoundaryQueue` for the next split point.

```python
    def process_chunk(self, chunk: bytes) -> None:
        """Route *chunk* to the correct encoder(s), splitting at boundaries.

        If the chunk spans one or more boundaries, it is split at the exact
        frame positions and the encoder is rotated for each boundary crossed.
        """
        if self._encoder is None:
            raise RuntimeError("Call start() before processing chunks")

        chunk_frames = len(chunk) // BYTES_PER_FRAME
        offset = 0

        while chunk_frames > 0:
            next_boundary = self._queue.peek_next()

            if next_boundary is None:
                # No upcoming boundaries — write everything to current encoder
                self._encoder.write(chunk[offset:])
                self._current_frame += chunk_frames
                break

            frames_to_boundary = next_boundary.frame_position - self._current_frame

            if frames_to_boundary <= 0:
                # Boundary is at or behind current position — consume it and rotate
                self._queue.pop_next()
                self._rotate_encoder()
                continue

            if chunk_frames <= frames_to_boundary:
                # Entire remaining chunk fits before the next boundary
                self._encoder.write(chunk[offset:])
                self._current_frame += chunk_frames
                chunk_frames = 0
            else:
                # Chunk spans the boundary — split at the exact frame
                split_bytes = frames_to_boundary * BYTES_PER_FRAME
                self._encoder.write(chunk[offset:offset + split_bytes])
                self._current_frame += frames_to_boundary
                offset += split_bytes
                chunk_frames -= frames_to_boundary
                self._queue.pop_next()
                self._rotate_encoder()
```

**Key design decisions:**

1. **`peek_next()` before `pop_next()`**: The processor peeks at the next boundary without removing it. Only after the boundary frame position is actually reached does it `pop_next()` to consume it. This allows the boundary to be modified (by drift correction) right up until the moment it is consumed.

2. **`frames_to_boundary <= 0` guard**: If a boundary is at or behind the current frame (e.g., because it was added late or drift correction shifted it backward past the current position), the processor consumes it immediately and rotates without writing any data. This prevents stale boundaries from accumulating.

3. **Multi-boundary chunks**: The `while chunk_frames > 0` loop handles the (rare) case where a single chunk spans two or more boundaries. Each boundary triggers an encoder rotation before continuing with the remainder of the chunk.

4. **Byte-level precision**: Splitting happens at `frames_to_boundary * BYTES_PER_FRAME` so every encoder receives frame-aligned data. No partial frames are ever written.

### `finish()` Method

```python
    def finish(self) -> None:
        """Close the final encoder and fire the segment-complete callback."""
        if self._encoder is not None and not self._finished:
            self._encoder.close()
            if self._on_segment_complete:
                self._on_segment_complete(
                    self._segment_index,
                    self._segment_start_frame,
                    self._current_frame,
                )
            self._finished = True
```

Called once after all chunks have been processed (EOF). Closes the last active encoder and fires the callback for the final segment.

### `_rotate_encoder()` Method

```python
    def _rotate_encoder(self) -> None:
        """Close the current encoder, fire callback, and start a new one."""
        if self._encoder is not None:
            self._encoder.close()
            if self._on_segment_complete:
                self._on_segment_complete(
                    self._segment_index,
                    self._segment_start_frame,
                    self._current_frame,
                )

        self._segment_index += 1
        self._segment_start_frame = self._current_frame
        self._encoder = self._start_encoder(self._segment_index)
```

Mirrors the `SplitProcessor._rotate_encoder()` pattern: close current encoder, fire callback with the completed segment's index and frame range, increment the segment counter, and create the next encoder.

### Comparison with Static SplitProcessor

| Aspect | `SplitProcessor` | `DynamicSplitProcessor` |
|--------|-------------------|------------------------|
| Boundary source | `list[int]` at construction | `BoundaryQueue` (live) |
| Boundary lookup | `self._boundaries[self._segment_index]` | `self._queue.peek_next()` |
| Boundary consumption | Implicit (index advances) | Explicit `pop_next()` |
| Thread safety | Not needed (static list) | Queue is thread-safe |
| Late/stale boundaries | N/A | Handled (`frames_to_boundary <= 0`) |

### Thread Safety Considerations

- `BoundaryQueue.peek_next()` and `pop_next()` are protected by a `threading.Lock` inside the queue.
- The `DynamicSplitProcessor` itself is **not** thread-safe and must only be called from the consumer thread (which is the single consumer loop in the orchestrator).
- The `TimingIntegrator` may call `replace_future()` from a timer thread concurrently with the consumer calling `peek_next()` / `pop_next()`. This is safe because all queue operations are serialized by the queue's internal lock.

## Tests

Test file: `dev/tests/test_orchestrator.py`

All tests use a mock encoder object with `write(bytes)` and `close()` methods, and a real `BoundaryQueue`.

- [ ] `test_dynamic_split_no_boundaries` — Create a `DynamicSplitProcessor` with an empty `BoundaryQueue`. Call `start()`, then `process_chunk()` with 3 chunks of 4800 frames (19200 bytes) each. Assert: (a) the single encoder received all 3 chunks' data via `write()`, (b) `close()` was never called on the encoder (no rotation), (c) `current_frame == 14400`, (d) `segment_index == 0`. Call `finish()` and assert the encoder's `close()` was called exactly once and `on_segment_complete` fired with `(0, 0, 14400)`.

- [ ] `test_dynamic_split_at_boundary` — Add a `BoundaryEntry(frame_position=4800, segment_index=0)` to the queue. Call `start()`, then `process_chunk()` with a 4800-frame chunk. Assert: (a) the first encoder received the entire chunk, (b) `_rotate_encoder()` was triggered (first encoder closed, second encoder created), (c) `on_segment_complete` was called with `(0, 0, 4800)`, (d) `segment_index == 1`. Send a second chunk and assert it goes to the second encoder.

- [ ] `test_dynamic_split_spanning_boundary` — Add a boundary at frame 2400. Send a single 4800-frame chunk. Assert: (a) the first encoder received exactly `2400 * 4 = 9600` bytes, (b) the second encoder received exactly `2400 * 4 = 9600` bytes, (c) `on_segment_complete` fired with `(0, 0, 2400)`, (d) `current_frame == 4800`.

- [ ] `test_dynamic_split_multiple_boundaries` — Add boundaries at frames 1000, 2000, and 3000. Send a single 4800-frame chunk. Assert: (a) four encoders were created (segments 0-3), (b) encoder 0 received `1000 * 4 = 4000` bytes, encoder 1 received `1000 * 4 = 4000` bytes, encoder 2 received `1000 * 4 = 4000` bytes, encoder 3 received `1800 * 4 = 7200` bytes, (c) `on_segment_complete` fired 3 times for segments 0, 1, 2 with correct frame ranges, (d) `segment_index == 3`.

- [ ] `test_dynamic_split_start_creates_encoder` — Call `start()` and assert `start_encoder` was called with argument `0`. Assert the returned encoder is stored as the active encoder.

- [ ] `test_dynamic_split_finish_closes_encoder` — Call `start()`, process one chunk, call `finish()`. Assert: (a) the encoder's `close()` was called exactly once, (b) `on_segment_complete` was called with the correct segment index, start frame, and end frame, (c) calling `finish()` a second time does not call `close()` again (idempotent).
