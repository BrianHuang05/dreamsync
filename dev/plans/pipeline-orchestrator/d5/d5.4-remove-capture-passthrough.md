# D5.4 — Remove capture_pipeline Pass-through

## Deliverable
D5 — CLI Integration

## Prerequisites
- D5.1 complete: `capture_orchestrator` replaces `capture_pipeline` in `session.py`
- D5.2 complete: orchestrator lifecycle is wired independently of the live loop
- Understanding of the current `run_live_to_govee()` signature and its `capture_pipeline` parameter
- Understanding of how the new `CaptureOrchestrator` works: it runs its own FFmpeg subprocess for audio capture and does NOT consume audio frames from the PortAudio feature extraction loop

## Description

The current `run_live_to_govee()` function in `live.py` accepts a `capture_pipeline` parameter (type `Any | None`) and calls `capture_pipeline.feed(frame, last_features, stream_t)` on every audio frame from the PortAudio callback. This was the old synchronous capture approach where the feature extraction audio loop doubled as the capture audio source.

With the new `CaptureOrchestrator`, audio capture is completely independent. The orchestrator spawns its own FFmpeg subprocess that captures audio directly from the system audio device (e.g., VB-CABLE Output). It does not need any audio frames from the PortAudio loop. Therefore, the `capture_pipeline` parameter and its `.feed()` call must be removed from `run_live_to_govee()`.

This change affects two files:
1. `src/dreamsync/live.py` — Remove the `capture_pipeline` parameter from `run_live_to_govee()` and the `capture_pipeline.feed()` call inside the audio processing loop.
2. `src/dreamsync/session.py` — Remove `capture_pipeline=capture_pipeline` from all `run_live_to_govee()` call sites.

### Verification

After these changes:
- `run_live_to_govee()` no longer has any knowledge of capture. It is purely a feature-extraction-to-renderer pipeline.
- The `CaptureOrchestrator` runs independently via its own threads (started in D5.2).
- No audio frame data flows from the PortAudio loop to the capture pipeline.

### Impact on Other Callers

Search for other callers of `run_live_to_govee()`:

```
src/dreamsync/session.py  — two call sites (updated above)
src/dreamsync/cli.py      — govee-live command handler (does NOT pass capture_pipeline currently)
```

The `govee-live` handler in `cli.py` does not pass `capture_pipeline` today — it relies on the session flow for capture. No changes needed there for the function signature change.

### Backward Compatibility

This is a breaking change to the `run_live_to_govee()` API. Any external code that passes `capture_pipeline=` will get a `TypeError`. This is intentional — the old capture approach is fully replaced. The function is internal (not part of the public API), so this is acceptable.
