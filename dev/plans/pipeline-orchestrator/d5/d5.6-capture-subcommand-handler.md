## Description

This sub-component adds the MP3 capture handler branch to the existing `capture` command handler in `cli.py`. When `--mp3` is specified, the handler creates a `CaptureOrchestrator`, starts it, waits for the specified duration (or Ctrl+C), then shuts it down and prints summary statistics.

The existing feature extraction handler (without `--mp3`) is preserved unchanged. The new code is inserted as a conditional branch that checks `args.mp3` first, with the old code in the `else` branch.

This handler is designed for standalone MP3 capture without any Govee device control or Spotify integration. It is the simplest way to record audio from the system audio device to per-song MP3 files.

### New Handler Code

Replace the entire `if args.command == "capture":` block with:

```python
    if args.command == "capture":
        if getattr(args, "mp3", False):
            # MP3 capture pipeline mode
            import signal
            import threading

            from dreamsync.capture.orchestrator import CaptureOrchestrator, OrchestratorConfig

            orch_cfg = OrchestratorConfig(
                sample_rate=args.sample_rate,
                channels=getattr(args, "channels", 2),
                device_pattern=args.device_pattern,
                output_dir=args.output_dir,
                naming=args.naming,
                log_dir=str(Path(args.output_dir) / "logs"),
            )
            orchestrator = CaptureOrchestrator(
                config=orch_cfg,
                on_segment_saved=lambda path, meta: print(
                    f"Saved: {Path(path).name}"
                ),
            )
            orchestrator.start()
            print(f"Capturing MP3 to {args.output_dir}/ (Ctrl+C to stop)")

            # Wait for duration or Ctrl+C
            stop = threading.Event()
            original_sigint = signal.getsignal(signal.SIGINT)
            signal.signal(signal.SIGINT, lambda *_: stop.set())

            try:
                stop.wait(timeout=args.duration)
            finally:
                signal.signal(signal.SIGINT, original_sigint)
                orchestrator.shutdown()
                stats = orchestrator.stats
                print(
                    f"Done: {stats['segments_completed']} segments, "
                    f"{stats['elapsed_seconds']:.0f}s captured"
                )

            return 0
        else:
            # Existing feature extraction capture (unchanged)
            stream, meta, telemetry_rows = capture_system_input_features_to_stream(
                duration_seconds=args.duration,
                sample_rate=args.sample_rate,
                channels=args.channels,
                device=args.device,
                frame_size=args.frame_size,
                hop_size=args.hop_size,
                telemetry_interval_seconds=args.heartbeat_seconds if args.heartbeat_seconds > 0 else None,
            )
            if args.jsonl:
                args.jsonl.parent.mkdir(parents=True, exist_ok=True)
                with args.jsonl.open("w", encoding="utf-8") as f:
                    for item in telemetry_rows:
                        f.write(json.dumps(item, separators=(",", ":")) + "\n")
                    for item in stream:
                        f.write(json.dumps(item, separators=(",", ":")) + "\n")
            else:
                for item in telemetry_rows:
                    print(json.dumps(item, separators=(",", ":")))
                for item in stream:
                    print(json.dumps(item, separators=(",", ":")))
            print(json.dumps({"capture_meta": meta}, separators=(",", ":")))
            return 0
```

### Detailed Behavior

#### 1. OrchestratorConfig Construction

```python
orch_cfg = OrchestratorConfig(
    sample_rate=args.sample_rate,          # from --sample-rate (default 44100)
    channels=getattr(args, "channels", 2), # from --channels (default 1, but 2 preferred for MP3)
    device_pattern=args.device_pattern,    # from --device-pattern (default "CABLE Output")
    output_dir=args.output_dir,            # from --output-dir (default "captured_songs")
    naming=args.naming,                    # from --naming (default "timestamp")
    log_dir=str(Path(args.output_dir) / "logs"),
)
```

Note: `args.sample_rate` defaults to 44100 in the capture subcommand, but the orchestrator's default is 48000. Users who want 48kHz should pass `--sample-rate 48000`. The CLI defers to the user's choice rather than hardcoding 48kHz.

#### 2. Signal Handling

The handler installs a SIGINT handler that sets a `threading.Event` instead of raising `KeyboardInterrupt`. This allows the `finally` block to run `orchestrator.shutdown()` for an orderly teardown (flushing the encoder, writing final metadata).

The original SIGINT handler is saved and restored in the `finally` block to avoid interfering with subsequent signal handling if the CLI process continues.

#### 3. Duration Wait

`stop.wait(timeout=args.duration)` blocks for at most `args.duration` seconds. If SIGINT arrives before the timeout, `stop.set()` unblocks the wait immediately. Either way, the `finally` block runs shutdown.

#### 4. Summary Output

After shutdown, the handler prints:
```
Done: 5 segments, 300s captured
```

This is a simplified version of the session shutdown summary (D5.2) — it omits `drift_corrections` since standalone capture without Spotify typically does not use drift detection.

#### 5. Return Value

The handler returns `0` on success (like all other CLI handlers).

### Error Handling

If `CaptureOrchestrator.start()` raises an exception (e.g., FFmpeg not found, audio device not available), the exception propagates to the caller. The CLI's top-level error handling should catch this and print a meaningful error message.

If `orchestrator.shutdown()` raises an exception in the `finally` block, it also propagates. This is acceptable — shutdown failures indicate a serious problem that should be reported.

### Thread Cleanup

The `orchestrator.shutdown()` method internally joins all threads and terminates subprocesses. After `shutdown()` returns, no background threads or processes remain. This is important for CLI tools that should exit cleanly.
