# D5.3 — Spotify Track Change Integration

## Deliverable
D5 — CLI Integration

## Prerequisites
- D5.1 complete: `capture_orchestrator` variable exists in `session.py`
- D5.2 complete: orchestrator start/stop lifecycle is wired
- `CaptureOrchestrator.on_track_change(timing_data: dict) -> None` — method that notifies the boundary queue of an immediate track change event
- `SpotifyQueueWatcher._on_track_changed` — internal callback attribute, callable `(new_track: SpotifyTrack, old_track: SpotifyTrack | None) -> None`
- `SpotifyTrack` fields: `.name`, `.artist`, `.album`, `.duration_ms`

## Description

This sub-component connects Spotify track change events to the capture orchestrator's boundary detection system. When Spotify reports that the currently playing track has changed, the orchestrator needs to know immediately so it can finalize the current segment and start a new one at the correct boundary.

The old code used `capture_pipeline.notify_track_changed(new, old)` which forwarded the raw `SpotifyTrack` objects to the `CompositeBoundaryDetector`. The new code uses `capture_orchestrator.on_track_change(timing_data)` which accepts a standardized `timing_data` dict containing the new track's duration and metadata.

The integration works by wrapping the existing `spotify_watcher._on_track_changed` callback. The wrapper first calls the original callback (which prints "Spotify: now playing ...") and then calls `capture_orchestrator.on_track_change()` with a timing data dict built from the new track's metadata.

This wiring is done in the capture orchestrator construction section of `session.py`, after both the `spotify_watcher` and `capture_orchestrator` are created but before the orchestrator is started (D5.2). The Spotify track change callback fires asynchronously from the Spotify polling thread, so `on_track_change()` must be thread-safe (which it is, as documented in D3).

## Implementation Details

### Insertion Point

This code is inserted in the "4e. Capture pipeline" section of `session.py`, after the `CaptureOrchestrator` is constructed (D5.1) but before the "5. Signal handling" section. It replaces the old Spotify track change integration that used `capture_pipeline.notify_track_changed()`.

### Code

```python
        # Connect Spotify track changes to capture orchestrator
        if spotify_watcher is not None and capture_orchestrator is not None:
            _orig_on_track = spotify_watcher._on_track_changed

            def _capture_track_changed(new, old, _orig=_orig_on_track):
                """Forward Spotify track change to capture orchestrator.

                Calls the original callback first (for logging), then notifies
                the orchestrator with formatted timing data.
                """
                if _orig:
                    _orig(new, old)
                capture_orchestrator.on_track_change({
                    "song_durations": [new.duration_ms / 1000.0],
                    "current_playback_time": 0.0,
                    "current_song": {
                        "song_title": new.name,
                        "artist": new.artist,
                        "album": getattr(new, "album", None),
                    },
                })

            spotify_watcher._on_track_changed = _capture_track_changed
```

### Timing Data Format

The `timing_data` dict passed to `on_track_change()`:

```python
{
    "song_durations": [float],        # Single-element list with new track duration in seconds
    "current_playback_time": 0.0,     # Always 0.0 — track just started
    "current_song": {
        "song_title": str,            # new.name
        "artist": str,                # new.artist
        "album": str | None,          # new.album (via getattr for safety)
    },
}
```

Key design decisions:
- `current_playback_time` is always `0.0` because a track change means the new track is at position 0.
- `song_durations` contains only the new track's duration (not the full queue). The periodic timing updates (D5.2) provide the full queue view; track change events are point-in-time signals.
- `album` uses `getattr(new, "album", None)` for defensive access, though `SpotifyTrack` does have an `album` field.

### Callback Wrapping Pattern

The wrapper uses a default argument `_orig=_orig_on_track` to capture the original callback by value. This is a Python closure pattern that prevents issues if `spotify_watcher._on_track_changed` is reassigned later.

The original callback (`_orig`) is called first to preserve the existing behavior (printing "Spotify: now playing '...' by ..."). If the original callback raises an exception, the orchestrator notification is skipped — this is intentional to avoid masking Spotify errors.

### Thread Safety

The `_capture_track_changed` wrapper is called from the `SpotifyQueueWatcher`'s polling thread. The `capture_orchestrator.on_track_change()` method is thread-safe (it enqueues a boundary event into the `BoundaryQueue`, which uses `queue.Queue` internally). No additional synchronization is needed.

### Removal of Old Code

The old Spotify integration code within the `if capture:` block is removed as part of D5.1. Specifically, this old code is no longer present:

```python
# OLD — removed in D5.1:
if spotify_watcher is not None:
    _orig_on_track = spotify_watcher._on_track_changed
    def _capture_track_changed(new, old, _orig=_orig_on_track):
        if _orig:
            _orig(new, old)
        capture_pipeline.notify_track_changed(new, old)
    spotify_watcher._on_track_changed = _capture_track_changed
```

The new code (above) replaces it with the orchestrator-compatible version.

### Error Handling

If `capture_orchestrator.on_track_change()` raises an exception, it should be caught and logged rather than crashing the Spotify polling thread. Wrap the call:

```python
            def _capture_track_changed(new, old, _orig=_orig_on_track):
                if _orig:
                    _orig(new, old)
                try:
                    capture_orchestrator.on_track_change({
                        "song_durations": [new.duration_ms / 1000.0],
                        "current_playback_time": 0.0,
                        "current_song": {
                            "song_title": new.name,
                            "artist": new.artist,
                            "album": getattr(new, "album", None),
                        },
                    })
                except Exception as exc:
                    print(f"Capture: track change notification failed: {exc}")
```
