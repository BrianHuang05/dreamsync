# D5.5 — Capture Subcommand Arguments

## Deliverable
D5 — CLI Integration

## Prerequisites
- Existing `capture` subcommand in `cli.py` with arguments: `--duration`, `--sample-rate`, `--channels`, `--device`, `--frame-size`, `--hop-size`, `--heartbeat-seconds`, `--jsonl`
- Understanding of `OrchestratorConfig` fields (D1.1): `output_dir`, `naming`, `device_pattern`, `sample_rate`, `channels`
- New arguments must coexist with existing feature extraction arguments (the `--mp3` flag switches between old and new behavior)

## Description

This sub-component adds four new command-line arguments to the existing `capture` subcommand in `cli.py`. These arguments control the new MP3 capture pipeline (via `CaptureOrchestrator`), which is activated by the `--mp3` flag. When `--mp3` is NOT specified, the existing feature extraction capture behavior is preserved unchanged.

The new arguments are:
1. `--mp3` — Boolean flag that switches the capture subcommand from feature extraction mode to MP3 pipeline mode.
2. `--output-dir` — Directory path where captured MP3 files are saved (default: `"captured_songs"`).
3. `--naming` — Filename scheme: `"timestamp"` (default) or `"metadata"` (uses Spotify track info if available).
4. `--device-pattern` — DirectShow audio device name pattern for FFmpeg input (default: `"CABLE Output"`).

These arguments are added to the `capture` subparser in the `build_parser()` function.

### New Arguments

```python
    # -- MP3 capture pipeline arguments --
    capture.add_argument(
        "--mp3",
        action="store_true",
        default=False,
        help="Enable MP3 capture pipeline (records per-song MP3 files from system audio).",
    )
    capture.add_argument(
        "--output-dir",
        type=str,
        default="captured_songs",
        help="Output directory for captured MP3 files (default: captured_songs).",
    )
    capture.add_argument(
        "--naming",
        choices=["timestamp", "metadata"],
        default="timestamp",
        help="Filename scheme for captured songs: 'timestamp' (default) or 'metadata' (uses track info).",
    )
    capture.add_argument(
        "--device-pattern",
        type=str,
        default="CABLE Output",
        help="DirectShow audio device name pattern for FFmpeg input (default: 'CABLE Output').",
    )
```

### Argument Details

| Argument | Type | Default | Description |
|----------|------|---------|-------------|
| `--mp3` | `store_true` | `False` | Activates MP3 capture mode. Without this flag, the capture subcommand runs the existing feature extraction pipeline. |
| `--output-dir` | `str` | `"captured_songs"` | Filesystem path for MP3 output. Created automatically if it does not exist (by `FileNamer` in the orchestrator). |
| `--naming` | `choices` | `"timestamp"` | Controls output filenames. `"timestamp"` produces `capture_20260304_153045.mp3`. `"metadata"` produces `Artist_-_Song_Title.mp3` when metadata is available. |
| `--device-pattern` | `str` | `"CABLE Output"` | Substring match for the FFmpeg DirectShow audio input device. On Windows, `ffmpeg -list_devices true -f dshow -i dummy` lists available devices. VB-CABLE creates a device named "CABLE Output (VB-Audio Virtual Cable)". |

### Interaction with Existing Arguments

When `--mp3` is active:
- `--duration` is still required and controls how long the MP3 capture runs.
- `--sample-rate` is reused to set the `OrchestratorConfig.sample_rate` (though the orchestrator defaults to 48kHz — the CLI arg can override it).
- `--channels` is reused to set `OrchestratorConfig.channels`.
- `--device`, `--frame-size`, `--hop-size`, `--heartbeat-seconds`, `--jsonl` are ignored in MP3 mode (they are feature extraction specific).

When `--mp3` is NOT active:
- All new arguments (`--output-dir`, `--naming`, `--device-pattern`) are ignored.
- Existing feature extraction behavior is completely unchanged.
