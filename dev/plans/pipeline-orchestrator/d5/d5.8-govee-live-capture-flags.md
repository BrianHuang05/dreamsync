## Description

The `govee-live` command is a direct-to-device command that calls `run_live_to_govee()` without going through `run_session()`. Currently, it does not support capture at all — the `--capture` flags only exist on the `session` subcommand. This sub-component adds `--capture`, `--capture-dir`, and `--capture-naming` arguments to the `govee-live` subparser and wires them to create and manage a `CaptureOrchestrator` in the `govee-live` handler.

This gives users two ways to run capture:
1. `dreamsync session --config devices.yaml --capture` — full session with YAML config, auto-detect, health monitoring, etc.
2. `dreamsync govee-live --device-ip 10.0.0.1 --duration 300 --capture` — lightweight single-device mode with capture.

The `govee-live` handler creates a `CaptureOrchestrator`, starts it before calling `run_live_to_govee()`, and shuts it down in a `finally` block. Since `run_live_to_govee()` no longer accepts a `capture_pipeline` parameter (D5.4), the orchestrator runs independently.

Add orchestrator creation and lifecycle around the `run_live_to_govee()` call:

```python
    if args.command == "govee-live":
        # ... build multi_adapter (unchanged) ...

        # Create capture orchestrator if --capture flag is set
        capture_orchestrator = None
        if getattr(args, "capture", False):
            from dreamsync.capture.writer import check_ffmpeg

            if not check_ffmpeg():
                print("Capture: ffmpeg not found on PATH. Install ffmpeg to enable song capture.")
                print("Continuing without capture.")
            else:
                from dreamsync.capture.orchestrator import CaptureOrchestrator, OrchestratorConfig

                capture_dir = getattr(args, "capture_dir", "captured_songs")
                capture_naming = getattr(args, "capture_naming", "timestamp")
                orch_cfg = OrchestratorConfig(
                    sample_rate=48000,
                    channels=2,
                    output_dir=capture_dir,
                    naming=capture_naming,
                    log_dir=str(Path(capture_dir) / "logs"),
                )
                capture_orchestrator = CaptureOrchestrator(
                    config=orch_cfg,
                    on_segment_saved=lambda path, meta: print(
                        f"Capture: saved {Path(path).name} "
                        f"({meta.get('artist', 'unknown')} - {meta.get('song_title', 'unknown')})"
                    ),
                )
                print(f"Capture: enabled -> {capture_dir}/ (naming={capture_naming})")

        # Start capture before live loop
        if capture_orchestrator:
            capture_orchestrator.start()

        try:
            logs, summary = run_live_to_govee(
                multi_adapter=multi_adapter,
                duration_seconds=args.duration,
                ...
                # NOTE: capture_pipeline parameter is REMOVED (D5.4)
            )
        finally:
            if capture_orchestrator:
                capture_orchestrator.shutdown()
                stats = capture_orchestrator.stats
                print(
                    f"Capture: {stats['segments_completed']} songs saved, "
                    f"{stats['elapsed_seconds']:.0f}s captured, "
                    f"{stats['drift_corrections']} drift corrections"
                )

        # ... write logs/summary (unchanged) ...
        return 0
```

### 3. Detailed Handler Flow

1. Parse `--capture`, `--capture-dir`, `--capture-naming` from args.
2. If `--capture` is set, check for FFmpeg availability via `check_ffmpeg()`.
3. If FFmpeg is available, construct `OrchestratorConfig` with hardcoded `sample_rate=48000`, `channels=2` (capture quality settings independent of feature extraction).
4. Create `CaptureOrchestrator` with the config and a segment-saved callback.
5. Start the orchestrator (spawns FFmpeg subprocess and capture threads).
6. Run `run_live_to_govee()` as normal (it has no capture dependency).
7. In the `finally` block, shut down the orchestrator and print summary.

### 4. Key Design Decisions

**No Spotify integration in `govee-live` capture**: The `govee-live` command does not have Spotify flags, so no periodic timing or track change integration is wired. The capture orchestrator runs in "timing-less" mode, relying on silence detection or fixed-duration segments for boundary detection. This is acceptable for the `govee-live` use case (quick, direct-device sessions).

**Sample rate hardcoded to 48kHz**: Unlike D5.6 where the capture subcommand defers to `args.sample_rate`, the `govee-live` handler hardcodes 48kHz for capture. This matches the session flow (D5.1) and ensures consistent capture quality. The feature extraction `sample_rate` (which drives PortAudio) may be different (e.g., 44100).

**`getattr` for safety**: `getattr(args, "capture", False)` is used defensively in case the arguments are not present on the namespace (e.g., if parsed from a different subcommand path).

### 5. Existing `capture_pipeline` References

After D5.4, `run_live_to_govee()` no longer accepts `capture_pipeline`. The `govee-live` handler currently does NOT pass this parameter (it was only passed from `session.py`). So no removal is needed here — we only need to add the new orchestrator logic.

However, verify that no `govee-live` code path references `capture_pipeline` before making changes. A search for `capture_pipeline` in the `govee-live` handler section should return zero results.
