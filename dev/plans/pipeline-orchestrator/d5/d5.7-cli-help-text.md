# D5.7 — CLI Help Text Updates

## Deliverable
D5 — CLI Integration

## Prerequisites
- D5.5 complete: new arguments (`--mp3`, `--output-dir`, `--naming`, `--device-pattern`) added to `capture` subparser
- D5.8 complete (or concurrent): `govee-live` and `session` capture flags updated
- Understanding of current help text structure in `cli.py`

## Description

This sub-component updates the CLI help text across the `capture`, `session`, and `govee-live` subcommands to document the new MP3 capture pipeline functionality. This includes updating subcommand descriptions, adding usage examples to the epilog text, and ensuring all new arguments have clear, consistent help strings.

Good help text is critical for discoverability. Users running `dreamsync capture --help` should immediately understand that `--mp3` enables a different mode of operation, and running `dreamsync session --help` should show that `--capture` now uses the new orchestrator pipeline.

## Implementation Details

### 1. Update `capture` Subcommand Description

Current:
```python
capture = sub.add_parser("capture", help="Capture system input and emit feature JSONL.")
```

New:
```python
capture = sub.add_parser(
    "capture",
    help="Capture system audio (feature JSONL or per-song MP3 files).",
    epilog=(
        "Examples:\n"
        "  # Feature extraction (original mode):\n"
        "  dreamsync capture --duration 60\n"
        "\n"
        "  # MP3 capture pipeline (record per-song MP3 files):\n"
        "  dreamsync capture --duration 300 --mp3 --output-dir ./songs --naming metadata\n"
        "\n"
        "  # MP3 capture with custom audio device:\n"
        "  dreamsync capture --duration 600 --mp3 --device-pattern 'Stereo Mix' --sample-rate 48000\n"
    ),
    formatter_class=argparse.RawDescriptionHelpFormatter,
)
```

### 6. Help String Consistency Rules

All new help strings follow these conventions:
- Use "MP3" (uppercase) consistently, not "mp3" or "Mp3"
- Default values are documented in parentheses: `(default: captured_songs)`
- Argument choices are listed explicitly: `'timestamp' (default) or 'metadata'`
- Device-specific terminology uses Windows DirectShow naming
- Examples use realistic paths and durations

```
                         [--device-pattern DEVICE_PATTERN]

options:
  -h, --help            show this help message and exit
  --duration DURATION   Capture duration in seconds.
  --sample-rate SAMPLE_RATE
                        Input sample rate.
  --channels CHANNELS   Input channel count.
  --device DEVICE       Optional input device id.
  --frame-size FRAME_SIZE
                        Frame size in samples.
  --hop-size HOP_SIZE   Hop size in samples.
  --heartbeat-seconds HEARTBEAT_SECONDS
                        Telemetry heartbeat period during capture (0 disables).
  --jsonl JSONL         Write feature stream to JSONL path (defaults to stdout).
  --mp3                 Enable MP3 capture pipeline (records per-song MP3 files from system audio).
  --output-dir OUTPUT_DIR
                        Output directory for captured MP3 files (default: captured_songs).
  --naming {timestamp,metadata}

  # MP3 capture with custom audio device:
  dreamsync capture --duration 600 --mp3 --device-pattern 'Stereo Mix' --sample-rate 48000
```
