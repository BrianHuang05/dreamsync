# D1.5 — Callback Wiring

## Deliverable
D1 — Orchestrator Core

## Prerequisites
- D1.2 complete: `CaptureOrchestrator.__init__` stores `on_segment_saved` callback and instantiates all sub-modules
- D1.3 complete: Consumer thread structure exists in `_consumer_loop()`
- The following sub-modules exist and are understood:
  - `FileNamer.next_filename(metadata)` returns an MP3 path string
  - `MetadataWriter.write_sidecar(mp3_path, metadata)` writes a JSON sidecar
  - `EncoderProcess.close()` / `.wait()` finalizes an MP3 file
  - `SplitProcessor.on_segment_complete` callback signature: `(segment_index, start_frame, end_frame)`

## Description

The orchestrator exposes a single user-facing callback: `on_segment_saved(mp3_path: str, metadata: dict)`. This callback fires after each audio segment is fully finalized — meaning the encoder process has closed the MP3 file and the JSON sidecar has been written. It gives external code (CLI, UI, show engine) a hook to react to each completed segment without polling.

In D1, the callback is **stored** during construction and a private `_on_segment_complete()` method is defined as the internal dispatch point. The actual wiring into the `SplitProcessor` data path happens in D2 (Capture Data Path), which connects `SplitProcessor.on_segment_complete` to call `_on_segment_complete()`. This separation keeps D1 focused on the orchestrator's own structure.

The callback runs on the **consumer thread**, not the main thread. Callers who need thread-safe handling (e.g., updating a UI) must manage their own synchronization.

### Internal Dispatch Method

```python
def _on_segment_complete(
    self,
    segment_index: int,
    start_frame: int,
    end_frame: int,
) -> None:
    """Handle segment completion — write sidecar and fire user callback.

    Called from the consumer thread when a segment boundary is
    crossed and the encoder for the previous segment is finalized.

    This method:
    1. Increments the segment counter
    2. Builds metadata dict from boundary and pipeline state
    3. Writes the JSON sidecar file
    4. Fires the user's ``on_segment_saved`` callback (if set)

    Parameters
    ----------
    segment_index:
        Zero-based index of the completed segment.
    start_frame:
        First frame of the completed segment (inclusive).
    end_frame:
        Last frame of the completed segment (exclusive).
    """
    self._segments_completed += 1

    # Build metadata for sidecar and callback
    metadata = {
        "segment_index": segment_index,
        "start_frame": start_frame,
        "end_frame": end_frame,
        "duration_frames": end_frame - start_frame,
        "duration_seconds": (end_frame - start_frame) / self._config.sample_rate,
        "sample_rate": self._config.sample_rate,
        "channels": self._config.channels,
        "bitrate": self._config.bitrate,
    }

    # Retrieve the MP3 path from the file namer's most recent output.
    # In D2, the SplitProcessor's start_encoder callback will have
    # already called FileNamer.next_filename() and stored the path.
    # For now, mp3_path is passed via the wiring in D2.
    mp3_path = ""  # Placeholder — set by D2 wiring

    # Write JSON sidecar
    try:
        from dreamsync.capture.metadata_writer import SegmentMetadata

        seg_meta = SegmentMetadata(
            start_frame=start_frame,
            end_frame=end_frame,
            sample_rate=self._config.sample_rate,
            channels=self._config.channels,
            bitrate=self._config.bitrate,
            segment_index=segment_index,
        )
        self._metadata_writer.write_sidecar(mp3_path, seg_meta)
    except Exception as exc:
        self._logger.log(
            "sidecar.write_error",
            level="WARNING",
            category="output",
            data={"error": str(exc), "segment_index": segment_index},
        )

    # Fire user callback
    if self._on_segment_saved is not None:
        try:
            self._on_segment_saved(mp3_path, metadata)
        except Exception as exc:
            self._logger.log(
                "callback.error",
                level="WARNING",
                category="output",
                data={"error": str(exc), "segment_index": segment_index},
            )
```

### How This Gets Wired (D2 Preview)

In D2, `_on_segment_complete` will be connected to the `SplitProcessor`:

```python
# D2 will do this in start():
self._split_processor = SplitProcessor(
    boundaries=...,
    start_encoder=self._create_encoder,
    on_segment_complete=self._on_segment_complete,  # <-- D1.5
)
```

The `SplitProcessor` calls `on_segment_complete(segment_index, start_frame, end_frame)` each time it crosses a boundary, which maps directly to `_on_segment_complete()`.

### Callback Contract

The `on_segment_saved` callback has the following contract:

```python
def on_segment_saved(mp3_path: str, metadata: dict) -> None:
    """Called after each segment is fully saved to disk.

    Parameters
    ----------
    mp3_path:
        Absolute path to the written MP3 file.
    metadata:
        Dictionary containing segment information:
        - segment_index (int): Zero-based segment number
        - start_frame (int): First frame (inclusive)
        - end_frame (int): Last frame (exclusive)
        - duration_frames (int): Total frames in segment
        - duration_seconds (float): Duration in seconds
        - sample_rate (int): Audio sample rate
        - channels (int): Audio channel count
        - bitrate (str): Encoding bitrate (e.g., "192k")

    Notes
    -----
    - Runs on the consumer thread, not the main thread.
    - Exceptions in the callback are caught and logged; they do not
      crash the pipeline.
    - The MP3 file and its JSON sidecar both exist on disk when
      this callback fires.
    """
```

### Error Handling

- If `on_segment_saved` is `None`, the dispatch method still runs (writes sidecar, increments counter) but skips the callback invocation.
- If the callback raises an exception, it is caught, logged as a warning, and **does not** propagate to the consumer thread. The pipeline continues processing.
- If the sidecar write fails, it is logged as a warning and the user callback still fires (the MP3 file itself is still valid).

### Thread Context

```
Consumer thread:
    AudioBuffer.get() → chunk
    SplitProcessor.process_chunk(chunk)
        └─ boundary crossed
           └─ encoder.close()
              └─ on_segment_complete(idx, start, end)
                 └─ _on_segment_complete()          ← D1.5
                    ├─ segments_completed += 1
                    ├─ MetadataWriter.write_sidecar()
                    └─ on_segment_saved(path, meta)  ← user callback
```
