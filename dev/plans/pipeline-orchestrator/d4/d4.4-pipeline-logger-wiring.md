# D4.4 — PipelineLogger Wiring

## Deliverable
D4 — Recovery & Logging

## Prerequisites
- D1 (Orchestrator Core) — `CaptureOrchestrator` class shell with `__init__()`
- `OrchestratorConfig` dataclass with `log_dir` field (default `"./logs"`)
- `PipelineLogger` implemented and tested in `src/dreamsync/capture/pipeline_logger.py`

## Description

Wire the `PipelineLogger` into `CaptureOrchestrator.__init__()` so that all pipeline state transitions, errors, and recovery events can be logged in a structured format. The logger outputs to two destinations simultaneously: a JSONL file (for machine parsing and post-session analysis) and stderr (for human-readable console monitoring during live sessions).

The logger is the pipeline's observability backbone. Every other D4 sub-component (D4.2 capture recovery, D4.3 encoder recovery, D4.5 event catalog, D4.7 shutdown logging) depends on `self._logger` being available. Additionally, D2 and D3 components use the logger for normal operational events (capture started, encoder spawned, boundary crossed, etc.).

## Implementation Details

### File Modified
`src/dreamsync/capture/orchestrator.py`

### Import Addition
```python
from dreamsync.capture.pipeline_logger import PipelineLogger
```

### Wiring in `__init__()`

Add the following in `CaptureOrchestrator.__init__()`, after config storage but before module instantiation that needs logging:

```python
self._logger = PipelineLogger(
    log_dir=config.log_dir,
    console_level="INFO",
    file_level="DEBUG",
)
```

### Constructor Parameters

| Parameter | Type | Value | Description |
|-----------|------|-------|-------------|
| `log_dir` | `str` | `config.log_dir` (default `"./logs"`) | Directory for JSONL log files. Created automatically if missing. |
| `console_level` | `str` | `"INFO"` | Minimum level for console (stderr) output. Filters out DEBUG-level noise like per-chunk events. |
| `file_level` | `str` | `"DEBUG"` | Minimum level for JSONL file output. Captures everything including high-volume chunk-level events. |

### PipelineLogger API Surface

The `PipelineLogger` instance provides one generic `log()` method and six convenience methods for common categories:

```python
# Generic log method
self._logger.log(
    level: str,        # "DEBUG", "INFO", "WARNING", "ERROR"
    category: str,     # "pipeline", "capture", "encoder", "split", "boundary", "timing", "recovery"
    event: str,        # Event name (e.g., "started", "ffmpeg_started")
    data: dict | None, # Arbitrary structured data
    frame_position: int,  # Current frame counter value
)

# Convenience methods (each sets category + default level automatically)
self._logger.capture_event(event, frame_position=0, **data)   # category="capture", level=INFO
self._logger.encoder_event(event, frame_position=0, **data)   # category="encoder", level=INFO
self._logger.split_event(event, frame_position=0, **data)     # category="split", level=INFO
self._logger.boundary_event(event, frame_position=0, **data)  # category="boundary", level=INFO
self._logger.timing_event(event, frame_position=0, **data)    # category="timing", level=INFO
self._logger.recovery_event(event, frame_position=0, **data)  # category="recovery", level=WARNING
```

### Output Destinations

**JSONL file** (`{log_dir}/pipeline.jsonl`):
```json
{"timestamp":"2026-03-04T15:30:00.000000+00:00","level":"INFO","category":"pipeline","event":"started","data":null,"frame_position":0}
```

**Console (stderr)**:
```
15:30:00.000 [INFO   ] pipeline:started  frame=0
```

The console handler is set to INFO level, meaning DEBUG events (like `chunk_read`) are only written to the JSONL file. This prevents console flooding during long capture sessions where thousands of chunk events would be emitted.

### Initialization Order

The logger should be instantiated early in `__init__()` so that subsequent module instantiations can use it for startup logging:

1. `self._config = config` (OrchestratorConfig)
2. `self._logger = PipelineLogger(...)` **(D4.4)**
3. `self._capture = CaptureProcessManager(...)` (D2)
4. `self._recovery = RecoveryManager(...)` (D4.1)
5. Buffer, split processor, boundary queue, etc.

Note: The logger could also be instantiated after `self._capture` since the capture manager does its own internal logging via Python's `logging` module. The important thing is that `self._logger` is available before `start()` is called.

### Log Directory Creation

`PipelineLogger.__init__()` automatically creates the log directory if it does not exist (`Path(log_dir).mkdir(parents=True, exist_ok=True)`). No additional directory creation logic is needed in the orchestrator.

### Thread Safety

`PipelineLogger` uses Python's `logging` module internally, which is thread-safe. The producer thread, consumer thread, and main thread can all call `self._logger.log()` concurrently without additional synchronization.
