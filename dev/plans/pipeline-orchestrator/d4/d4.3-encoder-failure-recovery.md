# D4.3 — Encoder Failure Recovery

## Deliverable
D4 — Recovery & Logging

## Prerequisites
- D4.1 (RecoveryManager Wiring) — `self._recovery` available in `CaptureOrchestrator`
- D4.4 (PipelineLogger Wiring) — `self._logger` available for encoder event logging
- D2 (Capture Data Path) — `_on_segment_complete()` implemented, `EncoderProcess` instances managed in `self._encoders`
- `RecoveryManager.handle_encoder_failure()` implemented with retry/fallback/skip cascade

## Description

Add encoder failure handling to the `_on_segment_complete()` callback so that when an `EncoderProcess` exits with a non-zero return code, the pipeline attempts a recovery cascade: first retry the encoding, then fall back to writing raw PCM data, and finally skip the segment if all else fails. This prevents a single FFmpeg encoder failure from crashing the pipeline or silently losing data.

The encoder failure path is less critical than capture failure (D4.2) because encoder failures are isolated to a single segment — the capture stream continues regardless. However, the recovery cascade ensures maximum data preservation: even if the MP3 encoder fails, the raw PCM data can be saved for later re-encoding.

### Encoder Failure Handling in `_on_segment_complete()`

The `_on_segment_complete()` method is called by the consumer thread when a segment boundary is crossed and the current encoder needs to be finalized. After calling `encoder.wait()`, check the return code and handle failures:

```python
def _on_segment_complete(
    self, segment_index: int, start_frame: int, end_frame: int
) -> None:
    """Finalize an encoder process and write its sidecar metadata.

    Called by the consumer thread when SplitProcessor crosses a boundary.
    """
    encoder = self._encoders[segment_index]
    rc = encoder.wait(timeout=30.0)

    if rc != 0:
        self._logger.recovery_event(
            "encoder_failure",
            frame_position=end_frame,
            segment_index=segment_index,
            exit_code=rc,
            stderr=encoder.stderr_output,
        )
        result = self._recovery.handle_encoder_failure(
            segment_info={
                "segment_index": segment_index,
                "output_path": encoder.output_path,
                "pcm_data": encoder.buffered_input,  # raw PCM for fallback
                "start_frame": start_frame,
                "end_frame": end_frame,
            },
            start_encoder_fn=lambda info: self._retry_encoder(info),
        )
        self._logger.recovery_event(
            "encoder_recovery_result",
            frame_position=end_frame,
            segment_index=segment_index,
            result=result,  # "retried", "fallback", or "skipped"
        )
        if result == "skipped":
            return  # No sidecar for skipped segments

    # Write sidecar metadata (same as D2 normal path)
    self._write_segment_sidecar(segment_index, start_frame, end_frame)
```

### Recovery Cascade

The `RecoveryManager.handle_encoder_failure()` method implements a three-step cascade:

**Step 1: Retry** — Spawn a new `EncoderProcess` for the same segment using the provided `start_encoder_fn`. The retry count is controlled by `RecoveryConfig.encoder_retry_count` (default 1). If the retry encoder completes successfully, returns `"retried"`.

**Step 2: Fallback (.raw)** — If retry fails (or `start_encoder_fn` is not provided), attempt to write the raw PCM data to a `.raw` file alongside the intended `.mp3` path. This preserves the audio data for manual re-encoding later. Returns `"fallback"`.

**Step 3: Skip** — If both retry and fallback fail, log an error and return `"skipped"`. The segment is lost but the pipeline continues.

### Retry Encoder Helper

```python
def _retry_encoder(self, segment_info: dict) -> object | None:
    """Spawn a new EncoderProcess to re-encode a failed segment.

    Returns the encoder object on success, None on failure.
    """
    try:
        output_path = segment_info["output_path"]
        encoder = EncoderProcess(
            output_path=output_path,
            sample_rate=self._config.sample_rate,
            channels=self._config.channels,
            bitrate=self._config.bitrate,
        )
        encoder.start()
        # Feed the buffered PCM data to the new encoder
        pcm_data = segment_info.get("pcm_data")
        if pcm_data:
            encoder.stdin.write(pcm_data)
        encoder.stdin.close()
        rc = encoder.wait(timeout=60.0)
        if rc == 0:
            return encoder
        return None
    except Exception:
        self._logger.log(
            "WARNING", "recovery", "encoder_retry_failed",
            data={"segment_index": segment_info.get("segment_index")},
            frame_position=segment_info.get("end_frame", 0),
        )
        return None
```

### Segment Info Dict Structure

The `segment_info` dict passed to `handle_encoder_failure()`:

| Key | Type | Description |
|-----|------|-------------|
| `segment_index` | `int` | Zero-based segment number |
| `output_path` | `str` | Intended MP3 output file path |
| `pcm_data` | `bytes \| None` | Raw PCM data for the segment (for fallback) |
| `start_frame` | `int` | First frame of the segment |
| `end_frame` | `int` | Last frame of the segment |

### Sidecar Handling After Recovery

- **`"retried"`** — The retry encoder produced a valid MP3. The sidecar is written normally with the segment metadata. No special fields needed.
- **`"fallback"`** — A `.raw` file was written instead of `.mp3`. The sidecar is still written, but `output_file` in the metadata points to the `.raw` path, and an additional `"encoding_fallback": true` field is added to `source_timing_data`.
- **`"skipped"`** — No output file exists. No sidecar is written. The method returns early.
