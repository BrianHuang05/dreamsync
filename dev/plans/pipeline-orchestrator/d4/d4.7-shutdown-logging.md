# D4.7 — Shutdown Logging

## Deliverable
D4 — Recovery & Logging

## Prerequisites
- D4.4 (PipelineLogger Wiring) — `self._logger` available in `CaptureOrchestrator`
- D1 (Orchestrator Core) — `stop()` method with thread join logic
- D2 (Capture Data Path) — `self.stats` property providing pipeline statistics

## Description

Add a structured summary log event to the `stop()` method so that when the pipeline shuts down, a final `pipeline:stopped` event is emitted containing aggregate statistics about the session. This summary provides a single log entry that captures the essential metrics of the entire capture session: how many segments were completed, total elapsed time, total frames processed, and any recovery events that occurred.

The shutdown summary is critical for post-session analysis. A monitoring system or human operator can look at a single log line to determine whether the session completed successfully, how long it ran, and whether any data was lost. The JSONL format allows automated parsing for session quality dashboards.

### File Modified
`src/dreamsync/capture/orchestrator.py`

### Shutdown Sequence in `stop()`

The `stop()` method already handles thread shutdown (from D1). The logging additions are:

```python
def stop(self) -> None:
    """Stop the pipeline and wait for all threads to exit."""
    self._logger.log(
        "INFO", "pipeline", "stopping",
        frame_position=self._buffer.frames_processed,
    )

    # Signal capture process to stop
    self._capture.stop()
    self._logger.capture_event(
        "ffmpeg_stopped",
        frame_position=self._buffer.frames_processed,
        exit_code=self._capture.exit_code if hasattr(self._capture, 'exit_code') else None,
    )

    # Wait for producer thread to exit (it will signal EOF on buffer)
    if self._producer_thread and self._producer_thread.is_alive():
        self._producer_thread.join(timeout=10.0)

    # Wait for consumer thread to drain buffer and exit
    if self._consumer_thread and self._consumer_thread.is_alive():
        self._consumer_thread.join(timeout=30.0)

    # Log final summary
    self._logger.log(
        "INFO", "pipeline", "stopped",
        data=self.stats,
        frame_position=self._buffer.frames_processed,
    )
```

### The `stats` Property

The `stats` property aggregates statistics from all pipeline sub-modules into a single dict. It is defined on `CaptureOrchestrator`:

```python
@property
def stats(self) -> dict:
    """Aggregate pipeline statistics for summary logging."""
    elapsed = time.time() - self._start_time if self._start_time else 0.0
    return {
        "segments_completed": self._segments_completed,
        "total_frames_processed": self._buffer.frames_processed,
        "total_duration_seconds": self._buffer.frames_processed / self._config.sample_rate,
        "elapsed_seconds": round(elapsed, 2),
        "capture_restarts": self._recovery.total_capture_restarts,
        "encoder_failures": self._recovery.total_encoder_failures,
        "gaps_recorded": len(self._recovery.gaps),
    }
```

### Stats Dict Fields

| Field | Type | Description |
|-------|------|-------------|
| `segments_completed` | `int` | Number of segments successfully finalized (MP3 + sidecar) |
| `total_frames_processed` | `int` | Total PCM frames that passed through the buffer |
| `total_duration_seconds` | `float` | Total audio duration in seconds (`frames / sample_rate`) |
| `elapsed_seconds` | `float` | Wall-clock time from `start()` to `stop()` |
| `capture_restarts` | `int` | Number of times FFmpeg was restarted due to failures |
| `encoder_failures` | `int` | Number of encoder processes that exited non-zero |
| `gaps_recorded` | `int` | Number of gap records from capture restarts |

### JSONL Output Format

The `pipeline:stopped` event in the JSONL log file:

```json
{
  "timestamp": "2026-03-04T15:30:00.000000+00:00",
  "level": "INFO",
  "category": "pipeline",
  "event": "stopped",
  "data": {
    "segments_completed": 12,
    "total_frames_processed": 34560000,
    "total_duration_seconds": 720.0,
    "elapsed_seconds": 721.35,
    "capture_restarts": 0,
    "encoder_failures": 0,
    "gaps_recorded": 0
  },
  "frame_position": 34560000
}
```

### Console Output Format

The console (stderr) shows a condensed version:

```
15:30:00.000 [INFO   ] pipeline:stopped  frame=34560000
```

Note: The console format (from `_ConsoleFormatter`) does not display the `data` dict. The full stats are only in the JSONL file. This is intentional — the console is for live monitoring, and the detailed stats are for post-session analysis.

### Segments Completed Counter

The `self._segments_completed` counter is incremented in `_on_segment_complete()` after successful segment finalization:

```python
def _on_segment_complete(self, segment_index, start_frame, end_frame):
    # ... encoder wait, sidecar write ...
    self._segments_completed += 1
```

### Graceful Shutdown Ordering

The logging calls in `stop()` must happen at the right points:

1. `pipeline:stopping` — First, before any shutdown actions
2. `capture:ffmpeg_stopped` — After `self._capture.stop()` returns
3. Thread joins — Wait for producer and consumer to finish
4. `pipeline:stopped` — Last, after everything is joined, includes final stats

This ensures the `frame_position` in the `stopped` event reflects the true final count after the consumer has drained the buffer.
