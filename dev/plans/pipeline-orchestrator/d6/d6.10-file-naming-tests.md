## Description

These tests verify that the pipeline produces output files with correct, predictable filenames following the configured naming pattern. File naming is critical for downstream workflows: users and automation tools need to find and identify output files by their names.

Two naming patterns are tested:
1. **Timestamp naming** (default): Files are named with a timestamp and a zero-padded segment counter. The pattern is `YYYY-MM-DD_HH-MM-SS_segment_NNNNNN.mp3`. This is the default pattern when no song metadata is available.
2. **Metadata naming**: When song metadata (artist + title) is available, files are named with the timestamp, sanitized artist name, and sanitized song title. The pattern is `YYYY-MM-DD_HH-MM-SS_Artist_-_Title.mp3`. Special characters in artist/title are replaced with underscores by `sanitize()`.

The tests exercise the `FileNamer` class integrated with the pipeline, verifying that:
- Filenames match the expected regex pattern
- The timestamp component is a valid date-time string
- The segment counter increments correctly
- Metadata naming correctly sanitizes artist and title strings
- Collision resolution works (appending `_2`, `_3`, etc. if a filename already exists)

### Pipeline Wiring with FileNamer

The encoder factory uses `FileNamer.next_filename()` to generate output paths:

```python
class TestFileNaming:
    """Verify output file naming patterns."""

    def _run_pipeline_with_namer(
        self,
        pcm_data: bytes,
        boundaries: list[int],
        output_dir: str,
        naming_pattern: str = "timestamp",
        song_metadata: list[dict] | None = None,
    ) -> list[str]:
        """Run pipeline with FileNamer, returning output file paths.

        Parameters
        ----------
        naming_pattern:
            ``"timestamp"`` or ``"metadata"``.
        song_metadata:
            List of dicts with ``artist`` and ``song_title`` keys, one per
            song.  Only used when ``naming_pattern="metadata"``.
        """
        namer = FileNamer(output_dir=output_dir, pattern=naming_pattern)
        output_files = []

        def start_encoder(segment_index: int):
            metadata = None
            if song_metadata and segment_index < len(song_metadata):
                metadata = song_metadata[segment_index]
            path = namer.next_filename(metadata=metadata)
            output_files.append(path)
            encoder = MockEncoderProcess(path)
            encoder.start()
            return encoder

        processor = SplitProcessor(
            boundaries=boundaries,
            start_encoder=start_encoder,
        )

        mock_capture = MockCaptureProcess(pcm_data)
        mock_capture.start()
        processor.run(read_chunks(mock_capture.stdout, chunk_ms=100))
        mock_capture.stop()

        return output_files
```

### Filename Regex Patterns

```python
# Timestamp pattern: YYYY-MM-DD_HH-MM-SS_segment_NNNNNN.mp3
TIMESTAMP_PATTERN = re.compile(
    r"^\d{4}-\d{2}-\d{2}_\d{2}-\d{2}-\d{2}_segment_\d{6}\.mp3$"
)

# Metadata pattern: YYYY-MM-DD_HH-MM-SS_SanitizedArtist_-_SanitizedTitle.mp3
METADATA_PATTERN = re.compile(
    r"^\d{4}-\d{2}-\d{2}_\d{2}-\d{2}-\d{2}_.+_-_.+\.mp3$"
)
```

### Sanitization Verification

The `sanitize()` function from `file_namer.py` replaces illegal filename characters:

```python
# Characters replaced by sanitize():
# < > : " / \ | ? * and control characters (\x00-\x1f)
#
# Examples:
# "AC/DC"       -> "AC_DC"
# "What?"       -> "What_"
# 'Say "Hello"' -> "Say _Hello_"
# "  .hidden  " -> "hidden"
# ""            -> "untitled"
```

### Timestamp Validation Helper

```python
from datetime import datetime

def _validate_timestamp_component(filename: str) -> None:
    """Extract and validate the timestamp from a filename."""
    # Extract the first 19 characters: YYYY-MM-DD_HH-MM-SS
    ts_str = filename[:19]
    # Parse as datetime to validate
    dt = datetime.strptime(ts_str, "%Y-%m-%d_%H-%M-%S")
    # Should be a recent timestamp (within the last hour)
    assert (datetime.now() - dt).total_seconds() < 3600
```

### Collision Resolution Behavior

`FileNamer._resolve_collision()` appends `_2`, `_3`, etc. if a file already exists:

```
2026-03-04_12-00-00_segment_000001.mp3       # first
2026-03-04_12-00-00_segment_000001_2.mp3     # if first exists
2026-03-04_12-00-00_segment_000001_3.mp3     # if first and second exist
```

This is handled internally by `FileNamer` and does not need explicit testing in the integration suite unless two pipeline runs happen within the same second (unlikely in tests).
