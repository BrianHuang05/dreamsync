# D2.1 — Producer Thread

## Deliverable
D2 — Capture Data Path

## Prerequisites
- D1 (Orchestrator Core) — `CaptureOrchestrator` class shell with `start()`, `stop()`, `shutdown()` lifecycle methods
- `CaptureProcessManager` (capture_process.py) — spawns FFmpeg, exposes `.stdout` binary pipe
- `pcm_reader.read_chunks()` (pcm_reader.py) — yields frame-aligned PCM byte chunks from a binary stream
- `AudioBuffer` (pcm_buffer.py) — thread-safe queue with backpressure and frame counter
- `RecoveryManager` (recovery_manager.py) — handles capture failure restart logic

## Description

The producer thread is one half of the two-thread architecture inside `CaptureOrchestrator`. It runs in a dedicated `threading.Thread` and is responsible for reading raw PCM audio data from the FFmpeg capture subprocess stdout pipe, chunking it into fixed-size frames via `read_chunks()`, and feeding each chunk into the shared `AudioBuffer`. The buffer acts as the synchronization point between the producer and consumer threads, applying backpressure when the consumer falls behind.

The producer also resets the `RecoveryManager` failure counter after each successful chunk read. If the FFmpeg process dies or the pipe raises an exception, the producer catches the error and delegates recovery to `RecoveryManager` (wired in D4). When the stream ends normally (FFmpeg exits, `read_chunks()` is exhausted), the producer signals EOF to the consumer by calling `AudioBuffer.signal_eof()`.

### Thread Startup

The producer thread is created and started inside `CaptureOrchestrator.start()`:

```python
import threading

# In CaptureOrchestrator.start():
self._producer_thread = threading.Thread(
    target=self._producer_loop,
    name="capture-producer",
    daemon=True,
)
self._producer_thread.start()
```

### Core Loop

```python
def _producer_loop(self) -> None:
    """Read PCM from FFmpeg stdout and feed into AudioBuffer.

    Runs in the 'capture-producer' thread. Exits when:
    - read_chunks() is exhausted (FFmpeg exits normally)
    - An exception occurs (capture failure)
    """
    try:
        for chunk in read_chunks(self._capture.stdout, self._config.chunk_ms):
            self._buffer.put(chunk)
            self._recovery.reset_capture_failure_count()
    except Exception:
        # Capture failure — delegate to RecoveryManager (D4)
        # RecoveryManager.handle_capture_failure() will attempt restart
        # If recovery succeeds, the producer loop is re-entered
        # If recovery fails, the pipeline shuts down
        ...
    finally:
        self._buffer.signal_eof()
```

### Chunk Size Calculation

Each chunk is exactly `chunk_bytes_for_ms(chunk_ms)` bytes. At the default 100ms chunk size with 48kHz stereo s16le audio:

```
chunk_bytes = chunk_bytes_for_ms(100)
            = int(100 / 1000.0 * 192000)
            = 19200 bytes
            = 4800 frames
            = 100ms of audio
```

The `chunk_ms` value comes from `CaptureOrchestrator`'s config (default 100).

### Backpressure Behavior

`AudioBuffer.put(chunk)` calls `queue.Queue.put()` which blocks if the queue is full (`max_chunks` reached, default 10). This means the producer will stall reading from FFmpeg stdout if the consumer cannot keep up. This is intentional — it prevents unbounded memory growth and provides natural flow control.

If the buffer is full for too long, FFmpeg's own internal buffer may overflow. This is acceptable because the consumer (encoder writing to disk) should always be faster than real-time audio capture.

### EOF Propagation

When `read_chunks()` reaches EOF (FFmpeg stdout pipe closed), the iterator is exhausted and the `for` loop exits naturally. The `finally` block calls `self._buffer.signal_eof()`, which enqueues a `None` sentinel into the buffer queue. The consumer thread detects this sentinel and exits its own loop.

### Thread Safety Notes

- `self._capture.stdout` is read only by the producer thread — no contention.
- `self._buffer.put()` is thread-safe (internal `queue.Queue`).
- `self._recovery.reset_capture_failure_count()` sets an integer counter — safe from the single producer thread.
- `self._buffer.signal_eof()` is called exactly once, from the `finally` block.

## Tests

All tests in `dev/tests/test_orchestrator.py`.

- [ ] `test_producer_reads_chunks_into_buffer` — Create a `BytesIO` with 5 chunks worth of known PCM data (5 * 19200 = 96000 bytes). Mock `self._capture.stdout` to return this stream. Run `_producer_loop()` synchronously. Assert that `self._buffer.get()` returns exactly 5 chunks of 19200 bytes each, matching the input data byte-for-byte.

- [ ] `test_producer_signals_eof_on_stream_end` — Create a `BytesIO` with 2 chunks of data. Run `_producer_loop()`. After the 2 data chunks, call `self._buffer.get()` a third time and assert it returns `None` (the EOF sentinel from `signal_eof()`).

- [ ] `test_producer_backpressure` — Create an `AudioBuffer` with `max_chunks=2`. Pre-fill the buffer with 2 chunks so it is full. Start `_producer_loop()` in a thread with a stream containing 1 more chunk. Assert the producer thread blocks (is alive but not progressing). Then call `self._buffer.get()` to free a slot and verify the producer proceeds and the third chunk arrives.

- [ ] `test_producer_resets_failure_count` — Mock `RecoveryManager.reset_capture_failure_count()`. Run `_producer_loop()` with a stream containing 3 chunks. Assert `reset_capture_failure_count()` was called exactly 3 times (once per successful chunk read).

- [ ] `test_producer_signals_eof_on_exception` — Mock `self._capture.stdout.read` to raise `OSError` after 1 chunk. Run `_producer_loop()`. Assert `signal_eof()` is still called (via the `finally` block) so the consumer is not left hanging.

- [ ] `test_producer_empty_stream_signals_eof` — Create a `BytesIO` with 0 bytes. Run `_producer_loop()`. Assert that `self._buffer.get()` returns `None` immediately (EOF with no data chunks).
