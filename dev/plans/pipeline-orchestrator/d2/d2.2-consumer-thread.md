# D2.2 — Consumer Thread

## Deliverable
D2 — Capture Data Path

## Prerequisites
- D1 (Orchestrator Core) — `CaptureOrchestrator` class shell with lifecycle methods
- D2.1 (Producer Thread) — producer is feeding chunks into `AudioBuffer`
- `AudioBuffer` (pcm_buffer.py) — thread-safe queue; `.get()` returns `bytes | None`
- `SplitProcessor` (split_logic.py) — routes PCM chunks to per-segment encoders, splitting at frame boundaries

## Description

The consumer thread is the second half of the two-thread architecture inside `CaptureOrchestrator`. It runs in a dedicated `threading.Thread` and is responsible for draining PCM chunks from the shared `AudioBuffer` and routing them through the `SplitProcessor`. The `SplitProcessor` handles the actual work of writing PCM data to the correct `EncoderProcess` and rotating encoders at segment boundaries.

The consumer loop is intentionally simple: it blocks on `AudioBuffer.get()`, passes each chunk to `SplitProcessor.process_chunk()`, and exits when it receives the `None` EOF sentinel. On exit, it calls `SplitProcessor.finish()` to close the final encoder and fire the last `on_segment_complete` callback.

The consumer thread is the only thread that writes to encoders, reads from `_encoders` dict, calls `FileNamer`, or calls `MetadataWriter`. This single-writer design eliminates the need for locks on these resources.

### Thread Startup

The consumer thread is created and started inside `CaptureOrchestrator.start()`, alongside the producer thread:

```python
import threading

# In CaptureOrchestrator.start():
self._consumer_thread = threading.Thread(
    target=self._consumer_loop,
    name="capture-consumer",
    daemon=True,
)
self._consumer_thread.start()
```

### Core Loop

```python
def _consumer_loop(self) -> None:
    """Drain AudioBuffer through SplitProcessor.

    Runs in the 'capture-consumer' thread. Exits when:
    - AudioBuffer.get() returns None (EOF sentinel from producer)
    """
    while True:
        chunk = self._buffer.get()
        if chunk is None:  # EOF sentinel
            break
        self._split.process_chunk(chunk)
    self._split.finish()
```

### Interaction with SplitProcessor

The `SplitProcessor` is initialized in D1 with the orchestrator's callbacks:

```python
self._split = SplitProcessor(
    boundaries=initial_boundaries,          # list[int] of cumulative frame positions
    start_encoder=self._start_encoder,      # D2.3 callback
    on_segment_complete=self._on_segment_complete,  # D2.4 callback
)
```

The `SplitProcessor.start()` method is called before the consumer thread begins, either during `CaptureOrchestrator.start()` or at the beginning of `_consumer_loop()`. This initializes the first encoder via `_start_encoder(0)`.

When `process_chunk(chunk)` is called:
1. The `SplitProcessor` tracks a global frame counter (`current_frame`).
2. If the chunk fits entirely within the current segment, it is written to the active encoder via `encoder.write(pcm_data)`.
3. If the chunk spans a boundary, it is split at the exact frame position. The first part goes to the current encoder, the encoder is rotated (close current, call `on_segment_complete`, start next via `_start_encoder`), and the remainder goes to the new encoder.
4. The split is byte-exact: `split_bytes = frames_remaining * BYTES_PER_FRAME` (where `BYTES_PER_FRAME = 4` for stereo s16le).

### finish() Behavior

When the consumer receives the EOF sentinel (`None`), it breaks out of the loop and calls `self._split.finish()`. This method:
1. Closes the final encoder's stdin via `encoder.close()`.
2. Fires `on_segment_complete(segment_index, segment_start_frame, current_frame)` for the last segment.
3. Sets an internal `_finished` flag to prevent double-finish.

### Graceful Shutdown Sequence

The full shutdown sequence across both threads:

```
1. FFmpeg exits (or is terminated by stop())
2. Producer: read_chunks() exhausted → finally: signal_eof()
3. Consumer: get() returns None → break → finish()
4. finish(): close final encoder → on_segment_complete() → write sidecar
5. Consumer thread exits
```

### Thread Safety Notes

- `self._buffer.get()` is thread-safe (internal `queue.Queue`).
- `self._split` is only accessed by the consumer thread — no contention.
- All downstream operations (`EncoderProcess.write()`, `FileNamer.next_filename()`, `MetadataWriter.write_sidecar()`) are invoked only from the consumer thread.

### SplitProcessor Interface Reference

```python
class SplitProcessor:
    def __init__(
        self,
        boundaries: list[int],
        start_encoder: Callable[[int], object],
        on_segment_complete: Callable[[int, int, int], None] | None = None,
    ) -> None: ...

    def start(self) -> None:
        """Initialize the first encoder via start_encoder(0)."""

    def process_chunk(self, chunk: bytes) -> None:
        """Route chunk to correct encoder(s), splitting at boundaries."""

    def finish(self) -> None:
        """Close the final encoder and fire on_segment_complete."""

    @property
    def current_frame(self) -> int: ...

    @property
    def segment_index(self) -> int: ...
```

All tests in `dev/tests/test_orchestrator.py`.

- [ ] `test_consumer_routes_chunks_to_encoder` — Create a mock encoder with a `write()` method. Configure `SplitProcessor` with no boundaries (single segment). Push 3 chunks of 19200 bytes into the `AudioBuffer`, then signal EOF. Run `_consumer_loop()` synchronously. Assert that the encoder's `write()` was called 3 times with the correct data.

- [ ] `test_eof_triggers_finish` — Push 1 chunk into `AudioBuffer`, then signal EOF. Run `_consumer_loop()`. Assert that `SplitProcessor.finish()` was called exactly once after all chunks were processed.

- [ ] `test_consumer_processes_all_chunks` — Push N=10 chunks into `AudioBuffer`, signal EOF. Run `_consumer_loop()`. Assert that `SplitProcessor.process_chunk()` was called exactly 10 times. Verify no chunks were dropped.

- [ ] `test_consumer_exits_on_eof` — Signal EOF immediately (no data chunks). Run `_consumer_loop()` in a thread. Assert the thread terminates within 1 second. Assert `SplitProcessor.finish()` was still called.

- [ ] `test_consumer_handles_boundary_split` — Configure `SplitProcessor` with a boundary at frame 4800 (1 chunk). Push 3 chunks into the buffer, signal EOF. Run `_consumer_loop()`. Assert that `on_segment_complete` was called for the first segment with `start_frame=0, end_frame=4800`, and a second encoder was started for the remainder.

- [ ] `test_consumer_blocks_on_empty_buffer` — Start `_consumer_loop()` in a thread with an empty buffer. Assert the thread is alive (blocked on `get()`). Then push 1 chunk and signal EOF. Assert the thread terminates and the chunk was processed.
