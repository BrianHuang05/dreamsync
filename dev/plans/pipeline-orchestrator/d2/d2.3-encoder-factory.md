# D2.3 — Encoder Factory (start_encoder callback)

## Deliverable
D2 — Capture Data Path

## Prerequisites
- D1 (Orchestrator Core) — `CaptureOrchestrator` class with `_config`, `_buffer`, `_logger` attributes
- D2.5 (Encoder Lifecycle Tracking) — `self._encoders: dict[int, EncoderProcess]` dict exists
- `EncoderProcess` (encoder_process.py) — per-segment FFmpeg encoder (PCM stdin -> MP3 file)
- `FileNamer` (file_namer.py) — generates deterministic output filenames
- `BoundaryQueue` (boundary_queue.py) — provides metadata for upcoming boundaries
- `PipelineLogger` (pipeline_logger.py) — structured event logging

## Description

The encoder factory is a callback method on `CaptureOrchestrator` that creates and starts a new `EncoderProcess` for each audio segment. It is passed to `SplitProcessor.__init__` as the `start_encoder` parameter and is called:

1. Once during `SplitProcessor.start()` to create the first encoder (segment 0).
2. Each time `SplitProcessor._rotate_encoder()` detects a boundary crossing, to create the next segment's encoder.

The factory is responsible for:
- Looking up metadata from `BoundaryQueue` for the given segment index.
- Generating the output MP3 file path via `FileNamer.next_filename()`.
- Creating an `EncoderProcess` with the correct audio parameters.
- Starting the encoder subprocess.
- Storing the encoder in `self._encoders` for later retrieval by `_on_segment_complete()` (D2.4).
- Logging the `encoder_started` event with frame position and output path.

### Implementation

```python
def _start_encoder(self, segment_index: int) -> EncoderProcess:
    # 1. Get metadata from BoundaryQueue for this segment
    metadata = self._get_segment_metadata(segment_index)

    # 2. Generate output file path
    mp3_path = self._file_namer.next_filename(metadata)

    # 3. Create encoder with audio parameters from config
    encoder = EncoderProcess(
        output_path=mp3_path,
        sample_rate=self._config.sample_rate,
        channels=self._config.channels,
        bitrate=self._config.bitrate,
    )

    # 4. Start the FFmpeg encoder subprocess
    encoder.start()

    # 5. Store in encoder tracking dict (D2.5)
    self._encoders[segment_index] = encoder

    # 6. Log the event
    self._logger.encoder_event(
        "encoder_started",
        frame_position=self._buffer.frames_processed,
        segment_index=segment_index,
        output_path=mp3_path,
    )

    return encoder
```

### Metadata Lookup Helper

```python
def _get_segment_metadata(self, segment_index: int) -> dict | None:
    """Retrieve metadata from BoundaryQueue for the given segment.

    The BoundaryQueue stores BoundaryEntry objects with optional metadata
    dicts containing song_title, artist, album, etc. Segment N's metadata
    comes from the boundary that starts segment N (i.e., the boundary at
    index N-1 for N > 0, or None for segment 0).
    """
    entry = self._boundary_queue.peek_next()
    if entry is not None and entry.metadata is not None:
        return entry.metadata
    return None
```

### FileNamer Integration

`FileNamer.next_filename(metadata)` generates paths in two patterns depending on configuration:

- **Timestamp pattern** (default): `{output_dir}/YYYY-MM-DD_HH-MM-SS_segment_NNNNNN.mp3`
- **Metadata pattern**: `{output_dir}/YYYY-MM-DD_HH-MM-SS_Artist_-_Title.mp3`

The metadata dict, if present, should have `"artist"` and `"song_title"` keys. If either is missing or if metadata is `None`, the timestamp pattern is used as fallback.

```python
class FileNamer:
    def __init__(self, output_dir: str = "./output", pattern: str = "timestamp") -> None: ...
    def next_filename(self, metadata: dict | None = None) -> str: ...
```

### EncoderProcess Lifecycle

The `EncoderProcess` spawns an FFmpeg subprocess that reads raw PCM from stdin and writes an MP3 file:

```python
class EncoderProcess:
    def __init__(self, output_path: str, sample_rate: int = 48000,
                 channels: int = 2, bitrate: str = "192k") -> None: ...

    def start(self) -> None:
        """Spawn FFmpeg encoder: ffmpeg -f s16le -ac {channels} -ar {rate} -i pipe:0 -c:a libmp3lame -b:a {bitrate} -y {output_path}"""

    def write(self, pcm_data: bytes) -> None:
        """Write raw PCM bytes to FFmpeg stdin."""

    def close(self) -> None:
        """Close stdin to trigger MP3 finalization."""

    def wait(self, timeout: float = 30.0) -> int:
        """Wait for FFmpeg to exit, return exit code."""

    @property
    def output_path(self) -> str: ...
```

### SplitProcessor Wiring

The factory is passed to `SplitProcessor` during orchestrator initialization:

```python
# In CaptureOrchestrator.__init__() or start():
self._split = SplitProcessor(
    boundaries=initial_boundaries,
    start_encoder=self._start_encoder,       # This method
    on_segment_complete=self._on_segment_complete,  # D2.4
)
```

`SplitProcessor` calls `start_encoder(segment_index)` and expects the returned object to have `write(bytes)` and `close()` methods. `EncoderProcess` satisfies this interface.
