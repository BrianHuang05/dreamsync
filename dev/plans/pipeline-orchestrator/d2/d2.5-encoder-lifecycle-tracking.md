# D2.5 — Encoder Lifecycle Tracking

## Deliverable
D2 — Capture Data Path

## Prerequisites
- D1 (Orchestrator Core) — `CaptureOrchestrator` class with `__init__`
- `EncoderProcess` (encoder_process.py) — per-segment FFmpeg encoder

## Description

The orchestrator maintains a dictionary that tracks all `EncoderProcess` instances by their segment index. This dict is the central registry that connects the encoder factory (D2.3) with the segment completion callback (D2.4). When `_start_encoder()` creates an encoder, it stores it in the dict. When `_on_segment_complete()` needs to wait for the encoder and retrieve its output path, it looks up the encoder by segment index.

The dict also serves as a record of all encoders created during the pipeline's lifetime, which is useful for shutdown cleanup (waiting on any in-progress encoders) and for diagnostics (inspecting stderr output from failed encoders).

Thread safety is guaranteed by design: the dict is only written and read by the consumer thread. The producer thread never touches it. Therefore, no locking is required.

## Implementation Details

### File
`src/dreamsync/capture/orchestrator.py`

### Data Structure

```python
class CaptureOrchestrator:
    def __init__(self, ...):
        ...
        # Encoder lifecycle tracking
        # Key: segment_index (int, 0-based)
        # Value: EncoderProcess instance for that segment
        self._encoders: dict[int, EncoderProcess] = {}
```

### Write Points (D2.3 — Encoder Factory)

The dict is written when `_start_encoder()` creates a new encoder:

```python
def _start_encoder(self, segment_index: int) -> EncoderProcess:
    ...
    encoder = EncoderProcess(
        output_path=mp3_path,
        sample_rate=self._config.sample_rate,
        channels=self._config.channels,
        bitrate=self._config.bitrate,
    )
    encoder.start()

    # Store in tracking dict
    self._encoders[segment_index] = encoder

    return encoder
```

### Read Points (D2.4 — Segment Completion)

The dict is read when `_on_segment_complete()` retrieves the encoder to wait for it:

```python
def _on_segment_complete(
    self, segment_index: int, start_frame: int, end_frame: int
) -> None:
    # Retrieve encoder by segment index
    encoder = self._encoders[segment_index]
    rc = encoder.wait(timeout=30.0)
    mp3_path = encoder.output_path
    ...
```

### Read Points (D2.6 — Build SegmentMetadata)

The dict is also read when building metadata to get the output file path:

```python
def _build_segment_metadata(
    self, segment_index: int, start_frame: int, end_frame: int
) -> SegmentMetadata:
    ...
    output_file=self._encoders[segment_index].output_path,
    ...
```

### Lifecycle Progression

For each segment, the encoder goes through these states:

```
1. Created & started  →  _start_encoder() stores in _encoders[N]
2. Receiving writes    →  SplitProcessor calls encoder.write(pcm)
3. Stdin closed        →  SplitProcessor calls encoder.close()
4. Wait for exit       →  _on_segment_complete() calls encoder.wait()
5. Completed           →  encoder stays in dict for diagnostics
```

At any point after step 4, the encoder's `output_path` points to a valid MP3 file (assuming rc=0).

### Concurrent Encoders

During a boundary crossing, two encoders briefly exist simultaneously:
1. The old encoder (stdin closed, FFmpeg finalizing MP3).
2. The new encoder (stdin open, receiving PCM data from `SplitProcessor`).

This is safe because `SplitProcessor._rotate_encoder()` performs these steps in order:
1. `encoder_old.close()` — close stdin of current encoder
2. `on_segment_complete(old_index, ...)` — callback fires, calls `wait()` on old encoder
3. `self._start_encoder(new_index)` — create and start new encoder

So by the time the new encoder is created, the old encoder has already been waited on and is finished.

### Shutdown Cleanup

During `CaptureOrchestrator.shutdown()` or `stop()`, any encoders that haven't been waited on should be cleaned up:

```python
def _cleanup_encoders(self) -> None:
    """Wait on any in-progress encoders and clean up resources."""
    for seg_idx, encoder in self._encoders.items():
        if encoder.is_alive():
            encoder.close()
            try:
                encoder.wait(timeout=10.0)
            except Exception:
                pass  # Log and continue
```

### Memory Considerations

The dict retains all `EncoderProcess` instances for the session lifetime. Each instance is lightweight (~200 bytes plus stderr output). For a typical 2-hour session with 30 songs, this is ~6KB — negligible. No pruning is needed.

### Thread Safety Analysis

| Operation | Thread | Contention Risk |
|-----------|--------|-----------------|
| `_encoders[N] = encoder` | Consumer (via `_start_encoder`) | None — single writer |
| `_encoders[N]` read | Consumer (via `_on_segment_complete`) | None — same thread |
| `_encoders[N].output_path` | Consumer (via `_build_segment_metadata`) | None — same thread |
| `_encoders` iteration | Consumer (via `_cleanup_encoders`) | None — only during shutdown |

The `AudioBuffer` queue is the single synchronization point between producer and consumer. Everything downstream of the buffer (including `_encoders`) is consumer-only.

## Tests

All tests in `dev/tests/test_orchestrator.py`.

- [ ] `test_encoder_dict_empty_initially` — Create a `CaptureOrchestrator` instance. Assert `self._encoders` is an empty dict (`{}`). Assert `len(self._encoders) == 0`.

- [ ] `test_encoder_stored_on_creation` — Call `_start_encoder(0)` (with mocked `EncoderProcess`). Assert `0 in self._encoders`. Assert `self._encoders[0]` is the same object returned by `_start_encoder()`. Assert `self._encoders[0].output_path` matches the path from `FileNamer`.

- [ ] `test_encoder_retrieved_on_completion` — Call `_start_encoder(0)` to store an encoder. Then call `_on_segment_complete(0, 0, 4800)`. Assert `self._encoders[0].wait()` was called, confirming the correct encoder was retrieved from the dict.

- [ ] `test_multiple_encoders_tracked` — Call `_start_encoder(0)`, `_start_encoder(1)`, `_start_encoder(2)` sequentially. Assert `len(self._encoders) == 3`. Assert each key (0, 1, 2) maps to a distinct `EncoderProcess` instance. Assert each has a different `output_path`.

- [ ] `test_encoder_dict_preserves_after_completion` — Call `_start_encoder(0)`, then `_on_segment_complete(0, 0, 4800)`. Assert `self._encoders[0]` still exists in the dict (not removed after completion). This ensures post-mortem access to stderr output for diagnostics.

- [ ] `test_encoder_dict_key_error_on_missing` — Assert that accessing `self._encoders[99]` raises `KeyError`. This validates that `_on_segment_complete` will fail explicitly if called with an unknown segment index rather than silently proceeding.
