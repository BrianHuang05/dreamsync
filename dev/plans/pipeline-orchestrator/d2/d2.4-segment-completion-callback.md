# D2.4 — Segment Completion Callback

## Deliverable
D2 — Capture Data Path

## Prerequisites
- D1 (Orchestrator Core) — `CaptureOrchestrator` class with `_logger`, `_config` attributes
- D2.3 (Encoder Factory) — encoders are created and stored in `self._encoders`
- D2.5 (Encoder Lifecycle Tracking) — `self._encoders` dict holds `EncoderProcess` per segment
- D2.6 (Build SegmentMetadata) — `_build_segment_metadata()` constructs the metadata dataclass
- `EncoderProcess` (encoder_process.py) — `.wait()` returns exit code, `.output_path` returns MP3 path
- `MetadataWriter` (metadata_writer.py) — `.write_sidecar()` writes JSON sidecar alongside MP3
- `PipelineLogger` (pipeline_logger.py) — `.split_event()` logs structured split events

## Description

The segment completion callback is invoked by `SplitProcessor` each time a segment boundary is crossed and the current encoder's stdin is closed. It is responsible for finalizing the completed segment: waiting for the encoder subprocess to finish writing the MP3 file, building a `SegmentMetadata` dataclass, writing a JSON sidecar file alongside the MP3, logging the completion event, and optionally firing a user-provided callback.

This method is the orchestrator's "segment done" hook — the single point where all post-segment actions converge. It is called from the consumer thread (via `SplitProcessor._rotate_encoder()` and `SplitProcessor.finish()`), so it runs sequentially with chunk processing. This is safe because the next encoder is already started and receiving data by the time this callback fires.

If the encoder exits with a non-zero return code, the method delegates to `RecoveryManager.handle_encoder_failure()` (wired in D4) instead of writing a sidecar.

```python
def _on_segment_complete(

    Only called from the consumer thread — no locking needed.

    Parameters
    ----------

    start_frame:
        First PCM frame of this segment (inclusive).
    end_frame:
        Last PCM frame of this segment (exclusive).
```

### Implementation

```python
def _on_segment_complete(
    self, segment_index: int, start_frame: int, end_frame: int
) -> None:
    # 1. Retrieve the encoder for this segment
    encoder = self._encoders[segment_index]

    # 2. Wait for FFmpeg encoder to finish writing MP3
    #    encoder.close() was already called by SplitProcessor._rotate_encoder()
    #    wait() blocks until the process exits or timeout
    rc = encoder.wait(timeout=30.0)

    # 3. Check encoder exit code
    if rc != 0:
        # Encoder failed — delegate to RecoveryManager (D4)
        self._logger.recovery_event(
            "encoder_failure",
            frame_position=end_frame,
            segment_index=segment_index,
            exit_code=rc,
            stderr=encoder.stderr_output,
        )
        # RecoveryManager.handle_encoder_failure() handles retry/fallback/skip
        # Wired in D4
        return

    # 4. Get output path from encoder
    mp3_path = encoder.output_path

    # 5. Build segment metadata (D2.6)
    metadata = self._build_segment_metadata(segment_index, start_frame, end_frame)

    # 6. Write JSON sidecar file alongside MP3
    sidecar_path = self._metadata_writer.write_sidecar(mp3_path, metadata)

    # 7. Log segment completion event
    self._logger.split_event(
        "segment_complete",
        frame_position=end_frame,
        segment_index=segment_index,
        mp3_path=mp3_path,
        sidecar_path=sidecar_path,
        duration_frames=end_frame - start_frame,
    )

    # 8. Fire user callback if registered
    if self._on_segment_saved:
        self._on_segment_saved(mp3_path, asdict(metadata))
```

### SplitProcessor Wiring

The callback is passed to `SplitProcessor` during orchestrator initialization:

```python
self._split = SplitProcessor(
    boundaries=initial_boundaries,
    start_encoder=self._start_encoder,           # D2.3
    on_segment_complete=self._on_segment_complete,  # This method
)
```

`SplitProcessor` calls this method in two places:
1. `_rotate_encoder()` — after closing the current encoder and before starting the next one.
2. `finish()` — for the final segment when EOF is reached.

In both cases, `encoder.close()` has already been called by `SplitProcessor` before this callback fires. The encoder subprocess is finalizing the MP3 file (flushing buffers, writing headers). `encoder.wait(timeout=30.0)` blocks until this completes.

### EncoderProcess.wait() Behavior

```python
def wait(self, timeout: float = 30.0) -> int:
    """Wait for FFmpeg to exit and return the exit code.

    Raises subprocess.TimeoutExpired if timeout is exceeded.
    Returns 0 on success, non-zero on failure.
    """
```

Common exit codes:
- `0` — success
- `1` — generic FFmpeg error
- `-15` — terminated by SIGTERM (on Unix)
- `1` on Windows — terminated

### MetadataWriter.write_sidecar() Behavior

```python
def write_sidecar(self, mp3_path: str, metadata: SegmentMetadata) -> str:
    """Write a JSON sidecar file atomically. Returns the sidecar path.

    Sidecar path is derived from mp3_path: song.mp3 -> song.json
    Writes atomically via temp file + os.replace() to prevent partial writes.
    """
```

The sidecar JSON contains all `SegmentMetadata` fields serialized by `_build_payload()`:
```json
{

    "segmentDurationFrames": 230400,
```

### User Callback

The `_on_segment_saved` callback is an optional function provided by the caller of `CaptureOrchestrator`. It receives the MP3 path and metadata dict:

```python
def _on_segment_saved(self, mp3_path: str, metadata: dict) -> None:
```

This allows external code (e.g., the session manager) to react to each saved segment — for example, uploading the file or updating a playlist.

### Timing Considerations

The `encoder.wait(timeout=30.0)` call blocks the consumer thread. During this time:
- The producer thread continues reading PCM from FFmpeg and enqueuing into `AudioBuffer`.
- Backpressure from a full buffer will stall the producer, which is acceptable.
- The next encoder is already started by `SplitProcessor._rotate_encoder()` before this callback fires, so it is ready to receive data once the consumer resumes.

In practice, the encoder finishes almost instantly after `close()` because it only needs to flush its output buffers and write MP3 frame headers. The 30-second timeout is a safety net for pathological cases.
