## Goal

Wire `SpotifyShowSession` into the existing `run_session()` and CLI. Add `--v3` and `--cache-dir` flags to the `session` subcommand. When `--v3` is used with `--spotify`, `run_session()` delegates to `run_v3_session()` instead of `run_live_to_govee()`. This is the final integration step that makes the v3 pre-sequenced playback runtime accessible to users.

```python
def run_v3_session(
    multi_adapter,
    spotify_watcher,
    *,

    profile: ProfileConfig | None = None,
    capture_dir: str = "captured_songs",
    stop_event: threading.Event,
    debug: bool = False,
) -> dict[str, Any]:

    cache = ShowCache(cache_dir)
    session = SpotifyShowSession(
        multi_adapter,

        cache=cache,
        profile=profile,
        capture_dir=capture_dir,
        debug=debug,
    )
    return session.run(stop_event)
```

## Validation: `--v3` without `--spotify`

The plan does **not** add a parser-level validation (argparse error) for `--v3` without `--spotify`. Instead, `run_session()` handles this at runtime:

- If `v3=True` but `spotify_watcher is None` (because `--spotify` wasn't passed or token was invalid), it prints a warning and falls back to v2.
- This is more user-friendly than a hard argparse error, since the token might expire mid-session.
